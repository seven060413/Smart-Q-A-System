> **读者**：AI 编码代理 / 后续开发同学
> **性质**：需求 + 实现规格。本文档不是代码变更记录，当前代码尚未实现本文档内容。
> **目标**：把“一次性学情诊断”升级为“逐点结果 → 错题集 → 错题知识图谱 → 历史趋势”的持续学习闭环。
> **约束**：迁移只增不改；不要修改已发布的 v8 / v9 迁移；不要改诊断规则和题库内容；不要合并 pansgo 与 K12-KGraph 的节点 id。

### 1.2 诊断引擎与状态

`src/quiz_engine.py` 已实现：

- 模式：`single`（单点）、`chapter`（章节）、`grade`（整年级摸底）。
- 连续答对 N 题判「掌握」，N=2/3/5；题量不足按 `min(N, 可用题数)`。
- 答错即终止该点掌握判定，追加 1 道确认题：
  - 确认题对 → `unstable`（不稳）；
  - 确认题错 → `weak`（薄弱），回溯先修。
- 总题量到上限，未测完 → `untested`（未测）。
- 可用题 < 2 → `insufficient`（题量不足）。

当前状态枚举：`pending` / `mastered` / `unstable` / `weak` / `untested` / `insufficient`。

### 1.5 前端现状

- 结果页只展示：汇总数字、单点结论、根因、章节计数、薄弱点再测。

### 1.6 已确认的缺口

1. 结果太笼统：数据有逐点状态，UI 只给汇总。
2. 答题记录服务端已落库，但没有读接口、没有本地 session id，用户读不回来。
3. 错题没有进入“我的”。
4. 没有错题知识图谱。
5. 没有跨会话的历史趋势。
6. 游客会话 `user_id` 为 NULL 且 24 小时过期，不能进历史。
7. `quiz_sessions` 没有 `dataset_version`；`quiz_attempts` 没有题目快照，题库更新后历史错题会变。
8. 结果 assessment 没有记录“最高答对难度”，无法区分“熟练”和“刚达标”。

## 2. 产品目标

### 2.1 三个维度

| 维度 | 回答的问题 | 载体 |
|---|---|---|
| 题目维度 | 我具体错在哪几道题？ | “我的” → 错题集 |
| 知识结构维度 | 这些错题背后是哪些知识点？先修关系是什么？ | 错题知识图谱 |
| 时间维度 | 我在变好还是变差？哪些点反复错？ | 学情趋势 |

### 2.2 用户故事

**A. 诊断完想知道“到底哪里不会”**

做完整年级摸底后，结果页不只显示“掌握 8、薄弱 3”，还要能展开到每个知识点的状态、答对/答错题数、最高答对难度。

**B. 想把错题攒起来**

一周后打开“我的 → 错题集（12）”，按章节/知识点/时间筛选，查看题干、自己的答案、正确答案、解析，能重做。

**C. 想知道错题背后的知识漏洞**

从错题点打开知识图谱，看到先修链和每个点的状态，知道该先补哪个。

**D. 想知道有没有进步**

月考前后各做一次诊断，打开“学情趋势”，看到掌握率、薄弱点数、持续薄弱和已改善。

### 2.3 非目标

- 不做新的题库或题目生成。
- 不改诊断难度阶梯和掌握规则。
- 不做社交、排行榜、家长端。
- 不做跨学科趋势。
- v1 不做力导向大图，不做复杂图表库。

## 3. 术语与状态

### 3.1 诊断状态（已有）

| 值 | 中文 | 含义 |
|---|---|---|
| `mastered` | 掌握 | 连续答对 N 题 |
| `unstable` | 不稳 | 答错后确认题答对 |
| `weak` | 薄弱 | 答错后确认题也错 |
| `untested` | 未测 | 题量上限到，没测完 |
| `insufficient` | 题量不足 | 可用题 < 2 |
| `pending` | 待测 | 内部状态，不展示 |

### 3.2 掌握等级（本次新增）

在 `mastered` 内部再分两级：

| 值 | 中文 | 规则 |
|---|---|---|
| `proficient` | 熟练 | `status=mastered` 且答对过 `challenge` / `advanced` 题 |
| `mastered` | 掌握 | `status=mastered` 且最高只答对 `basic` / `standard` |
| 其他 | 沿用状态 | `unstable` / `weak` / `untested` / `insufficient` |

实现要求：

- 引擎为每个知识点记录本次作答历史：`[{question_id, difficulty, correct}]`。
- `result.assessments[i]` 新增 `max_correct_difficulty`（`basic|standard|challenge|advanced|null`）和 `mastery_level`。
- `counts.mastered` 仍包含熟练 + 掌握，避免破坏现有前端；新增 `counts.proficient` 作为子集。
- 旧会话缺少这些字段时，读接口回退：`mastery_level = status`，`max_correct_difficulty = null`。

### 3.3 趋势指标

| 指标 | 定义 | 说明 |
|---|---|---|
| 已测 | `mastered + unstable + weak` | 不含未测 / 题量不足 |
| 掌握率 | `(proficient + mastered) / 已测` | 分母为 0 时返回 `null` |
| 薄弱率 | `weak / 已测` | |
| 覆盖率 | `已测 / scope_count` | `scope_count` 为本次范围知识点总数 |
| 持续薄弱 | 同一知识点最近连续 ≥2 次为 `weak` | |
| 已改善 | 相邻两次从 `weak/unstable` 变为 `mastered/proficient` | |
| 反复错题 | 同一 `question_id` 在多次作答中 `is_correct=0` ≥2 次 | |

## 4. 需求明细

### 4.1 P0：逐点结果清单

**用户看到什么**

结果页汇总下面，按章节分组列出每个被测知识点：

```text
第三章 一元一次方程                    本章：熟练 0 · 掌握 2 · 不稳 1 · 薄弱 1 · 未测 1
  熟练   一元一次方程的概念            连续 3 题，最高难度：拓展
  掌握   等式的性质                    连续 3 题，最高难度：提高
  不稳   去括号                        答对 2/3，错 1 题
  薄弱   去分母                        答对 0/2，错 2 题     [看错题] [看图谱] [再测]
  未测   实际问题与一元一次方程
```

**要求**

- 必须列出 `result.assessments` 的全部条目，不只是根因。
- 章节分组用 `chapter` / `chapter_label`。
- 支持筛选：全部 / 熟练 / 掌握 / 不稳 / 薄弱 / 未测 / 题量不足。
- 每行展示：状态、答对/答错题数（由 `asked` / `wrong` 长度计算）、最高答对难度。
- 操作：
  - 看错题：跳转错题集并带 `node_key` 过滤；
  - 看图谱：跳转知识图谱并带该 `node_key`；
  - 再测：以该知识点开一次单点诊断。
- 整年级模式：顶部保留章节汇总，但章节行必须可展开到逐点；不能只给数字。
- 单点模式：目标点放在最上面，其他回溯点按章节/深度排列。

**数据来源**

- 本次结果直接来自 start/answer 响应的 `result.assessments`。
- 重新打开历史结果时，来自 `GET /api/diagnose/sessions/{id}`。

**验收**

- 页面上列出的条目数 = `assessments.length`。
- 各状态数量与 `counts` 一致。
- 整年级模式能展开看到每个被测点。
- 熟练/掌握/不稳/薄弱/未测的筛选结果正确。

### 4.2 P0：会话恢复

**要求**

- 诊断开始成功后，前端把 `session_id` 写入本地存储：
  - key：`ikgr_last_diagnosis_session`
  - value：`{session_id, mode, created_at, question}`（只存必要字段，不存正确答案）。
- 诊断页打开时，如果有本地 session：
  - 调用 `GET /api/diagnose/sessions/{id}`；
  - 若会话仍 `active`，显示“上次诊断未完成，继续 / 重新开始”；
  - 若已 `completed`，显示“查看上次结果 / 重新开始”。
- 会话结束或用户选择“重新开始”后，更新或清除本地记录。
- 作答重试仍复用 `client_request_id`（现有逻辑）。

**验收**

- 关闭页面/刷新后，未完成会话能继续。
- 已完成结果能重新打开。
- 不把正确答案写入本地存储。

### 4.3 P1：错题集

**入口**

- “我的”页新增「错题集」一行，右侧显示未掌握错题数量。
- 可选：在“我的”页新增「学情趋势」一行。

**列表**

每道错题卡片包含：

- 题干、选项/配图；
- 学生答案；
- 正确答案；
- 解析；
- 知识点名称、章节、年级；
- 做错时间、来源诊断；
- 错题次数；
- 状态：待复习 / 已掌握 / 已忽略。

**筛选**

- 年级；
- 章节；
- 知识点；
- 状态（默认待复习）；
- 时间（最近 7/30/90 天）；
- 分页（cursor 或 limit/offset）。

**操作**

- 重做：以该 `node_key` 开单点诊断；
- 标记已掌握；
- 标记忽略；
- 查看知识图谱。

**规则**

- 数据来源：`quiz_attempts.is_correct = 0`，按 `user_id + dataset_version + question_id` 聚合。
- 同一道题错多次只显示一条，`wrong_count` 累加。
- 必须使用**作答时快照**，不能实时 join 当前题库（题库可能已更新）。
- 已掌握/忽略状态存独立表，不修改 attempts。
- 游客没有错题集；必须登录。

**验收**

- 错 1 题后，“我的”出现错题集入口且数量 +1。
- 卡片内容与作答时一致（即使题库重新种子）。
- 重做、标记已掌握、筛选都可用。
- 同一题错两次显示 `wrong_count=2`，列表仍只有一条。

### 4.4 P2：错题知识图谱

**入口**

- 结果页每个薄弱/不稳点的「看图谱」；
- 错题集卡片的「查看知识图谱」；
- 可选：错题集顶部「查看全部错题图谱」。

**图的内容**

- 种子：错题/薄弱知识点（1 个或多个）。
- 向上取 `depth=2` 层先修（可配置 1–3）。
- 向下取 0–1 层后继（可选）。
- 节点状态颜色：
  - 薄弱：红
  - 不稳：橙
  - 掌握：绿
  - 熟练：深绿
  - 未测：灰
- 边：
  - `strength=hard`：实线；
  - `strength=soft`：虚线；
  - 方向：先修 → 后继。

**v1 可视化要求**

- 使用**分层先修图**，不要力导向大图：
  - 按距离种子的深度分层；
  - 同层节点横向排列；
  - 层间用连线；
  - 节点可点击。
- 前端用 `view` + CSS 绘制，避免引入 Cytoscape。
- 移动端优先；节点过多时只显示种子 + 1 层，提供“展开更多”。

**交互**

- 点击节点：底部弹层显示知识点名称、状态、章节、答对/错题数；
- 操作：看错题、再测这个点、去学习；
- 多个种子共享先修时合并为一张图，不重复画。

**验收**

- 选择一个薄弱点，能看到它的先修链和状态颜色。
- hard/soft 边样式不同。
- 点击节点能跳错题/再测。
- 不出现 K12-KGraph 的节点 id。

### 4.5 P3：历史趋势

**入口**

- “我的 → 学情趋势”；
- 可选：诊断结果页底部「查看趋势」。

**页面结构**

```text
学情趋势
最近 4 次诊断 · 七年级 · 数学

掌握率   42% → 71%   ↑29%
薄弱点   8 → 3       ↓5
覆盖率   35% → 40%   ↑5%

[掌握率 / 薄弱点数趋势：v1 用数字 + 水平条形，v2 再上折线]

持续薄弱（2）
  一元一次方程        连续 3 次薄弱
  去分母              连续 2 次薄弱

已改善（3）
  整式的加减          薄弱 → 掌握
  等式的性质          不稳 → 掌握

[知识点状态时间线]
完全平方公式
  9/01 薄弱 → 9/15 不稳 → 9/30 掌握 → 10/15 熟练
```

**必须展示**

1. 最近 N 次（默认 10）会话的掌握率、薄弱数、覆盖率；
2. 本次 vs 上次 vs 首次的 delta；
3. 持续薄弱清单（连续 ≥2 次 weak）；
4. 已改善清单；
5. 知识点状态时间线（至少支持按章节筛选）；
6. 反复错题清单（同一题错 ≥2 次）。

**可比性规则（必须实现）**

- 只比较同一 `dataset_version` 的会话；版本变化时在趋势中插入分隔，不连线。
- 不同覆盖范围不能直接比较绝对数量；页面必须显示覆盖率，比较用率。
- 少于 2 次有效会话：显示“还没有足够数据形成趋势”。
- 游客会话不进入趋势；必须登录。
- `untested` / `insufficient` 不计入掌握率分母。
- 掌握率分母为 0 时显示“—”，不显示 0%。

**验收**

- 两次诊断后能显示掌握率变化。
- 同一知识点从薄弱 → 掌握能出现在“已改善”。
- 连续两次薄弱能出现在“持续薄弱”。
- 覆盖率不同时有提示，不误导。
- 题库版本变化时有分隔提示。
- 少于 2 次显示空状态。

### 5.2 写入要求

`create_session`：

- 写入 `dataset_version = dataset.version`；
- 写入 `scope_count = len(node_ids)`。

`answer_session`：

- 读取当前题目后，写入 attempts 的新字段：
  - `dataset_version`；
  - `difficulty`；

  - `prompt_snapshot`；
  - `choices_snapshot_json`；
  - `answer_snapshot`；
  - `explanation_snapshot`；
  - `figure_snapshot`。

### 5.3 兼容旧数据

- 旧 sessions / attempts 的新字段为 NULL。
- 读接口遇到 NULL：
  - `dataset_version` 回退 `pansgo.SOURCE_COMMIT`；
  - 快照回退当前 `questions` 表（按 `dataset_version + question_id` join）；
  - `mastery_level` 回退 `status`；
  - `max_correct_difficulty` 回退 `null`。
- 不要求回填旧数据。

### 5.4 掌握等级写入

`src/quiz_engine.py`：

- `TopicAssessment` 内部节点状态增加 `history`：
  ```json

  ```
- 每次 `answer()` 追加一条。
- `result()` 的 assessment 增加：
  - `max_correct_difficulty`：答对题中最高的难度（`basic < standard < challenge/advanced`）；

- `counts` 增加 `proficient`（子集，不改变 `mastered` 总数）。
- 旧结果没有这些字段时，读接口补齐默认值。

## 9. 规则与边界

### 9.1 趋势可比性

- 只比较同一 `dataset_version`。
- 覆盖率不同必须提示；比较用率，不用绝对数量。
- `untested` / `insufficient` 不进掌握率分母。
- 少于 2 次不画趋势。
- 游客不进趋势。

### 9.2 掌握等级

- 熟练 = 掌握 + 答对过拓展。
- 掌握 = 连续答对 N 题，但最高只到提高。
- 不要把 3 题的结果表述成“完全掌握”；UI 可显示“基于 3 题”。

### 9.3 游客

- 游客可做诊断、看本次结果、用本地 session 恢复。
- 游客没有错题集、历史、趋势。
- 游客会话 24 小时过期；登录后不自动迁移游客记录（除非后续单独做绑定）。

### 9.4 答案安全

- 作答前不返回 `answer` / `verify`。
- 错题集返回正确答案是合理的（已作答过），但必须校验用户所有权。
- 不把答案写入本地存储。

### 9.5 题量与覆盖

- 每点 4–5 题；N=5 时按实际题量判定。
- 整年级 40 题覆盖有限；趋势必须展示覆盖率。
- 未测不是掌握，也不是薄弱。

### 9.6 版本变化

- 题库重新种子/升级时，`dataset_version` 变化。
- 历史错题使用快照，不受影响。
- 趋势在版本变化处断开。
- 不强行合并不同版本的题目统计。
