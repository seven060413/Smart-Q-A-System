# 知识点关联 B 站视频实施记录

> 首期范围：五年级下册 59 个知识点（45 Concept + 14 Skill）。
> 审核方式：CLI / CSV。
> 播放形态：H5 折叠区内 `iframe`；APK 独立播放页 + `<web-view>`。

---

| 项 | 决策 |

| 首期覆盖 | 只覆盖五年级下册；其他年级问答正常，但暂无视频 |

## 2. 数据库

迁移 version 2：`knowledge_point_videos`，包含三张表：

- `videos`：B 站视频元数据；主键 `bilibili:{bvid}:{page}`
- `knowledge_point_videos`：`node_key → video` 映射 + 审核状态
- `video_candidates`：采集候选与原始响应

已应用到 `data/app/ikgr.db`；迁移前快照在 `data/app/backups/`。

为什么只按 `node_key` 关联：

- `message_knowledge_points` 中“本体”可能写 book 版本，前置/巩固写 full 版本；
- 同一个 `node_key` 在 book 与 full 中是稳定 ID；
- 不建 `graph_nodes` 外键，避免 `--force` 重导图谱时阻塞。

只有 `review_status='approved'` 且 `videos.status='active'` 会被接口返回。

## 3. 接口

### 3.1 视频查询

```http
GET /api/videos?node_key=math_5b_rjb_cpt20&node_key=math_5b_rjb_cpt18&limit=2
```

- 公开只读，不需要登录；
- `node_key` 可重复，一次最多 20 个；
- `limit` 1–5，默认 2；
- 返回 `items`（有视频的节点）和 `missing`（没有可用视频的节点）；
- `embed_url` 由服务端按 `bvid/page` 生成并校验，不接受客户端任意 URL。

### 3.2 问答/历史消息新增字段

`/api/ask` 与 `/api/conversations/{id}/messages` 增加：

- `prerequisite_gaps[i].id`
- `learning_path.body_id`
- `learning_path.prerequisite_ids`
- `learning_path.consolidation_ids`

旧消息由 `message_knowledge_points` 回填，不需要离线迁移历史 JSON。

## 6. 采集与审核 CLI

### 6.1 导出空白模板

```powershell
.venv/Scripts/python.exe scripts/collect_videos.py --export-seed data/video_candidates_5b.csv
```

生成 59 行五年级下册知识点模板，填写 `bvid`、`title` 等字段。

### 6.2 导入 CSV/JSON

```powershell
.venv/Scripts/python.exe scripts/collect_videos.py --from-csv data/video_candidates_5b.csv
.venv/Scripts/python.exe scripts/collect_videos.py --from-json data/video_candidates_5b.json
```

导入只写 `video_candidates` 和 `videos`，不会自动通过审核。

### 6.3 审核与补齐官方嵌入参数

```powershell
# 查看待审
.venv/Scripts/python.exe scripts/review_videos.py list --status pending

# 导出给老师/助教离线审核
.venv/Scripts/python.exe scripts/review_videos.py export --status pending --output data/review_5b.csv

# 通过（推荐加 --fetch-meta，自动补齐 aid/cid）
.venv/Scripts/python.exe scripts/review_videos.py approve --candidate-id 12 --rank 1 --reviewer teacher_a --note "内容匹配" --fetch-meta

# 拒绝
.venv/Scripts/python.exe scripts/review_videos.py reject --candidate-id 13 --reviewer teacher_a --note "广告/不匹配"

# 没有候选时手工新增并直接通过
.venv/Scripts/python.exe scripts/review_videos.py add --node-key math_5b_rjb_cpt20 --bvid BV1xx411c7mD --title "分数单位讲解" --reviewer teacher_a --fetch-meta

# 给已有视频批量补齐 aid/cid（例如旧演示数据、之前未联网审核的数据）
.venv/Scripts/python.exe scripts/review_videos.py resolve --limit 100 --interval 2
```

说明：

- `--fetch-meta` 调用 B 站公开 `view` 接口解析 `aid` / 对应分 P 的 `cid`；
  只在审核阶段联网，运行时不会访问 B 站；
- 官方嵌入 URL 需要 `isOutside=true&aid=...&bvid=...&cid=...&p=...`；
- 审核通过/拒绝必须写 `reviewer`；拒绝不会覆盖已通过视频的元数据。

## 7. B 站搜索适配器评估

**暂不启用实时搜索。** 原因：

- 本仓库没有 BiliLite 源码，也没有外部链接，无法验证其 `searchVideo()` 是否实际调用 WBI；
- 即使某个外部项目存在 `WbiSign.kt`，也只能证明它实现了签名工具，不能证明搜索接口使用了它；
- B 站 Web 搜索接口不是稳定公开 API，可能需要 WBI 签名、`buvid3` Cookie、真实 UA/Referer，匿名请求可能返回 `-412` / `-352`；
- 运行时不能搜索，采集也应低速率、可中断、保留原始响应。

当前策略：

- `scripts/collect_videos.py --search` 只打印说明，不发起请求；
- 先用人工/浏览器辅助整理 BV，走 CSV/JSON 导入；
- 等确认搜索接口可用、合规且稳定后，再单独实现可替换的 `search_provider`。

播放端默认只用 B 站官方嵌入播放器：

```text
https://player.bilibili.com/player.html?isOutside=true&aid={aid}&bvid={bvid}&cid={cid}&p={page}&autoplay=0&danmaku=0
```

如果浏览器提示“您当前的浏览器不支持 HTML5 播放器”：

- 优先改用 Chrome / Edge（Firefox 等可能缺少 H.264 解码器）；
- H5 播放器下方提供“移动版播放器”和“在 B 站打开”兜底；
- 移动版地址：`https://www.bilibili.com/blackboard/html5mobileplayer.html?bvid={bvid}&page={page}&danmaku=0&high_quality=1`

不使用 playurl 直链。

## 9. 常见问题

### 播放器提示“您当前的浏览器不支持 HTML5 播放器”

1. **优先换 Chrome / Edge 验证**。Firefox / Zen / 部分精简浏览器可能缺少 H.264 解码器，
   这不是 iframe 参数能修复的；需要安装系统编解码器或换浏览器。
2. 确认使用的是官方嵌入地址，并且带 `isOutside=true`、`aid`、`bvid`、`cid`、`p` 参数。
   可以用 `review_videos.py resolve` 为已有视频补齐 `aid/cid`。
3. 确认视频作者没有关闭“允许嵌入”；大会员/付费/版权内容可能无法外嵌。
4. H5 播放器下方点“移动版播放器”，或点“在 B 站打开”直接用 B 站页面播放。
5. APK 端 Android WebView 版本过低也可能触发同样的提示；建议升级系统 WebView，
   或点“在 B 站打开”/改用外部浏览器。

### 显示“暂无审核通过的视频”

1. 先确认浏览器实际请求的是本机后端，而不是旧地址：
   - H5 本机调试：`http://127.0.0.1:18080`
   - 手机 / APK：不能用 `127.0.0.1`，要用电脑 `ipconfig` 里的局域网 IPv4，并重新打包 APK
2. 在浏览器 Network 中看 `GET /api/videos?node_key=...&limit=2&_t=...`：
   - 期望 200，且 `items` 里有对应 `node_key`；
   - 如果请求 URL 是 `192.168.1.31`、云服务器或旧端口，说明前端用了旧构建/旧配置。
3. 前端每次展开都会带 `_t` 时间戳绕过缓存，后端 `/api/videos` 也返回 `Cache-Control: no-store`；
   如果仍为空，先硬刷新（Ctrl+F5）或重启 `npm run dev:h5`。
4. 如果看到“当前消息缺少知识点编号”，说明 `/api/ask` 是旧后端或消息来自旧数据，重新提问即可。

### 修改后没有生效

- 后端如果没有加 `--reload`，改代码后必须手动重启 uvicorn；
- H5 如果打开的是 `app/dist/build/h5` 旧产物，重新 `npm run build:h5` 或改用 `npm run dev:h5`；
- APK 的 `BASE_URL` 是打包时写死的，改地址后必须重新打包。

## 10. 已知限制

- APK 端 `<web-view>` 是原生全屏容器，不能在折叠卡内部播放；首期采用独立播放页。
- 五年级下册之外的知识点暂无视频，前端显示空状态。
- 同一个 BV 的多条候选共享一条 `videos` 元数据；正式导入时应保证同一 BV 的标题/时长一致。
- 视频失效巡检脚本尚未实现；后续可加 `scripts/check_videos.py`，标记 `videos.status='unavailable'`。
