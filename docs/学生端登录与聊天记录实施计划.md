# 学生端登录与聊天记录实施计划

## 目标

在现有知识图谱问答系统上，逐步增加学生注册、登录、跨设备聊天历史，并为后续老师端和多课程数据留好结构。每一阶段都要能单独审阅、解释和回退，避免一次性大改造成黑盒。

## 当前项目基线

- 后端：Python + FastAPI，问答入口目前是 `POST /api/ask`。
- 前端：`app/` 下的 uni-app + Vue 3，已有问答页和学习路径页。
- 知识图谱：原始图谱与五年级下册子图目前以 JSON 文件保存，后端启动时载入内存。
- 当前问答 API 不要求登录，也没有把提问和回答持久化为用户聊天历史。
- 后续目标：先做学生端；老师、班级分析和 DuckDB 分析后续再做。

#### 1. 后端现状

- 入口：[src/api.py](../src/api.py)。该模块在**导入时**（不是 lifespan 启动钩子）加载：
  - `load_full_graph()`：全量 `data/raw/math.json`，用于前置诊断、学习路径、章节溯源；
  - `load_nodes(data/processed/math_5b_knowledge_graph.json)`：五年级下册 59 个知识点，作为**实体链接候选**；
  - `QwenGenerator()`：读取 `.env` 中的 Qwen 配置。
- 路由只有两个：`GET /`（服务信息）、`POST /api/ask`（问答）。**没有用户、登录、会话、聊天历史、数据库相关代码。**
- 请求体只有 `question: str`，没有长度上限、空串校验或频率限制。
- 响应字段为：`answer`、`knowledge_point`、`prerequisite_gaps`（`[{name, required}]`）、`learning_path`（`{prerequisites, body, consolidation}`，拒答时为 `null`）、`source`、`refused`。内部 `prompt` 字段在返回前删除。
- 问答流程：`link_top(question, kp_nodes)` → 链接分数 `< 0.2` 拒答 → 否则用全量图做 `diagnose` / `build_learning_path` / `format_citation` → 同步调用 Qwen 生成。整个路由是同步 `def`，由 FastAPI 在线程池执行。
- CORS 当前为 `allow_origins=["*"]`、允许全部方法和请求头；未启用 Cookie 凭证。
- 进程模型：阿里云 systemd 托管单个 uvicorn 进程，端口 18080。

#### 2. 前端现状

#### 2. 关键设计决定

1. **账号与角色**：用户名 + 密码；注册接口固定创建 `student`；老师/管理员只能后台脚本创建。
2. **密码**：只用 Python 标准库 `hashlib.scrypt` 存哈希（含盐和参数），不新增第三方认证依赖，不存明文。
3. **登录凭证**：服务端生成随机不透明令牌，只存 SHA-256 到 `auth_sessions`，客户端用 `Authorization: Bearer`；30 天绝对过期、可撤销、多设备。选择它而不是 JWT，是因为本项目已有数据库，撤销/封禁更直接。
4. **前端存储**：`uni.setStorageSync('ikgr.auth.token', ...)`；H5 走 localStorage，需防 XSS；收到 401 清除本地令牌；不保存密码。
5. **游客**：未登录可问答，但不写任何数据库；游客带 `conversation_id` 返回 401；令牌无效不降级为游客。
6. **多轮会话**：一个会话保存多轮问答；MVP 每次回答仍只基于当前问题，不把历史消息传给模型。
7. **数据模型**：用户/会话/消息用 UUID 文本；图谱节点/边用整数主键；`graph_edge_targets` 统一承载标量 target 和 `target_name_to_ids` 列表，避免漏掉 635 条特殊边。
8. **历史可追溯**：助手消息保存 `graph_version_id`（主要版本）和 `context_graph_version_id`（全量诊断版本），以及知识点、出处、拒答状态、学习路径 JSON 快照。
9. **删除**：会话软删除；账号删除/匿名化由后台脚本执行；MVP 不自动清理。
10. **扩展**：SQL 放仓储层、时间用 Python 生成、避免 SQLite 专有写法，便于迁移 PostgreSQL；老师/班级、DuckDB 只预留结构，不实现。

#### 3. 接口示例

**注册（自动登录）**

```http
POST /api/auth/register
Content-Type: application/json

{
  "username": "xiaoming",
  "password": "<至少8位的用户密码>",
  "display_name": "小明"
}
```

成功 `201`：

```json
{
  "token": "ikgr_<随机令牌，仅此一次返回>",
  "token_type": "bearer",
  "expires_at": "2026-11-27T08:30:00.000Z",
  "user": {
    "id": "<uuid>",
    "username": "xiaoming",
    "display_name": "小明",
    "role": "student",
    "created_at": "2026-10-28T08:30:00.000Z",
    "last_login_at": "2026-10-28T08:30:00.000Z"
  }
}
```

- 用户名重复（大小写不敏感）→ `409 USERNAME_TAKEN`；
- 传 `role` 等未知字段 → `422 VALIDATION_ERROR`；
- 密码过短 → `422 VALIDATION_ERROR`，错误详情**不回显密码值**。

**登录**

```http
POST /api/auth/login
Content-Type: application/json

{ "username": "xiaoming", "password": "<用户密码>" }
```

成功 `200`：结构同注册响应（新令牌 + 用户信息）。

- 密码错误、账号不存在 → 都是 `401 INVALID_CREDENTIALS`，消息完全相同；
- 账号被禁用且密码正确 → `403 ACCOUNT_DISABLED`；
- 触发限流 → `429 RATE_LIMITED`，带 `Retry-After`。

**当前用户**

```http
GET /api/auth/me
Authorization: Bearer <令牌>
```

成功 `200`：返回 `id / username / display_name / role / created_at / last_login_at`，不返回密码哈希、令牌哈希或 `status`。

**退出**

```http
POST /api/auth/logout
Authorization: Bearer <令牌>
```

成功 `204 No Content`；重复调用仍返回 204（幂等），不泄露令牌是否曾经有效。

**统一错误结构**

```json
{
  "error": {
    "code": "INVALID_CREDENTIALS",
    "message": "用户名或密码错误",
    "details": null,
    "request_id": "<服务端请求 id>"
  }
}
```

#### 4. 认证流程（通俗解释）

1. **注册**：用户提交用户名/密码 → 服务端校验格式 → 用随机盐做 scrypt 哈希 → 写入 `users`，`role` 固定为 `student` → 生成随机令牌 → 数据库只存令牌的 SHA-256 → 明文令牌只返回这一次。
2. **登录**：按用户名（大小写不敏感）查用户 → 用 scrypt 校验密码 → 失败统一提示“用户名或密码错误” → 成功则新建一条 `auth_sessions` 记录并返回新令牌。
3. **访问受保护接口**：前端带 `Authorization: Bearer <令牌>` → 服务端对令牌做 SHA-256 → 查 `auth_sessions` → 检查未撤销、未过期、用户 `status='active'` → 得到用户身份。**请求里的 `user_id` 一律不参与身份判断。**
4. **退出**：把当前 `auth_sessions.revoked_at` 写为当前时间 → 该令牌立即失效；其他设备的令牌不受影响。
5. **过期**：默认 30 天绝对过期，不自动续期；过期后返回 `401 TOKEN_EXPIRED`，前端应清除本地令牌并重新登录。

### 目标

### Claude 提示词

```text

每一步说明现有 POST /api/ask 如何演进以及兼容性影响。更新实施计划，说明新旧接口变化、数据表、越权保护、前端操作流程和验证结果。不要实现教师端统计或 DuckDB 管道。
```

### 阶段记录

**状态：已完成（2026-10-29）。本阶段实现后端聊天持久化与前端历史会话，不包含教师端统计或 DuckDB 管道。**

#### 1. `POST /api/ask` 如何演进（兼容性说明）

**请求新增可选字段：**

```json
{
  "question": "为什么异分母分数相加要先通分",
  "conversation_id": "<可选，登录后指定>",
  "client_request_id": "<可选，客户端生成的请求 id，用于重试去重>"
}
```

**行为矩阵：**

| 认证 | `conversation_id` | 行为 |
|---|---|---|
| 无 | 无 | 游客问答，**不落库**；响应保留原字段，新增 `persisted=false` |
| 无 | 有 | `401 AUTH_REQUIRED`，不允许游客写历史 |
| 有效 | 有 | 校验会话属于当前用户，追加一轮问答 |
| 有效 | 无 | 自动创建新会话，再追加一轮问答；响应返回 `conversation_id` |
| 无效/过期 | 任意 | `401`，**不降级为游客**，避免“以为保存了其实没保存” |

**成功响应在原有字段上新增（不删除旧字段）：**

```json
{
  "answer": "……",
  "knowledge_point": "异分母分数加减法",
  "prerequisite_gaps": [{ "name": "通分方法", "required": true }],
  "learning_path": { "prerequisites": ["通分方法"], "body": "异分母分数加减法", "consolidation": ["分数混合运算"] },
  "source": "人教版五年级下册·分数的加法和减法",
  "refused": false,
  "persisted": true,
  "conversation_id": "<uuid>",
  "user_message_id": "<uuid>",
  "assistant_message_id": "<uuid>",
  "created_at": "2026-10-29T08:30:02.000Z"
}
```

- 幂等重放时额外返回 `deduplicated: true`，消息 id 与首次相同；
- 游客响应保持旧前端可用，旧前端会忽略新增的 `persisted` 字段；
- 原有 `/api/ask` 的回答内容、知识点、学习路径、出处、拒答字段均未改名。

#### 2. 新增会话历史接口

| 方法 | 路径 | 认证 | 说明 |
|---|---|---|---|
| GET | `/api/conversations?limit=20&cursor=...` | 是 | 当前学生的会话列表，游标分页 |
| POST | `/api/conversations` | 是 | 创建空会话（标题/课程可选） |
| GET | `/api/conversations/{id}` | 是 | 会话详情 |
| GET | `/api/conversations/{id}/messages?limit=50&cursor=...` | 是 | 消息游标分页，返回按时间正序 |
| DELETE | `/api/conversations/{id}` | 是 | 软删除会话，重复删除幂等 204 |

- 会话列表默认 20 条、最大 50；消息默认 50 条、最大 100。
- 游标对外是不透明字符串；内部用 `(last_message_at, rowid)` / `(created_at, rowid)` 排序，避免同一毫秒内 UUID 随机导致顺序错乱。
- 会话列表返回 `message_count`；消息返回 `refused`、`knowledge_point`、`source`、`prerequisite_gaps`、`learning_path`、`status`、`error_code/error_message` 等，不返回令牌/密码。
- 未实现改名接口（设计中的可选项）；删除是软删除，消息仍保留在库中。

#### 3. 数据表与字段

复用阶段 2 已建的 3 张表，**本阶段没有新增迁移**：

- `conversations`：`user_id`、`course_id`、`title`、`created_at`、`updated_at`、`last_message_at`、`deleted_at`。
- `messages`：问题/回答内容、`role`、`status`、`refused`、`knowledge_point`、`source`、`learning_path_json`、`prerequisite_gaps_json`、`graph_version_id`、`context_graph_version_id`、`reply_to_message_id`、`client_request_id`、`error_code`、`error_message`、`latency_ms`、时间字段。
- `message_knowledge_points`：本体 / 必需前置 / 建议前置 / 巩固延伸，带 `node_key`、`node_name`、`relation`、`ordinal` 和所属图谱版本。

**图谱版本：**

- 从 `graph_versions` 中按启用槽位读取 `math:book:math_5b_rjb`（实体链接/本体）和 `subject_full`（前置诊断/全量图）；
- 助手消息保存 `graph_version_id` 和 `context_graph_version_id`，历史答案可追溯；
- 如果数据库尚未导入图谱版本，消息仍会保存，只是跳过 `message_knowledge_points` 关联（不伪造版本）。

#### 4. 越权保护

1. 所有会话/消息接口的身份都来自 Bearer 令牌，**不读取请求体/query 里的 `user_id`**。
2. 会话查询一律带 `user_id = 当前用户`；访问别人的会话统一返回 `404 CONVERSATION_NOT_FOUND`，不泄露是否存在。
3. `/api/ask` 带 `conversation_id` 时先验证归属；游客带 `conversation_id` 返回 401。
4. 消息写入使用 `messages` 的 `(conversation_id, user_id)` 复合外键，应用层之外再加一道数据库约束。
5. 聊天记录只保存问题/回答/知识点等业务字段；测试确认没有把令牌、密码或密钥写进消息。
6. 当前课程默认数学；非默认课程必须是 `courses` 表中已存在的启用课程，学生不能通过接口随意创建课程记录。

#### 5. 生成失败与重试

- 登录用户提问时，先写入用户消息（短事务），再调用流水线/生成器；
- 生成失败（超时、上游错误、空回答）时：
  - 写入一条 `status='failed'` 的助手消息，`error_code='UPSTREAM_ERROR'`，`content=NULL`；
  - 返回 `502 UPSTREAM_ERROR`，错误 `details` 带 `conversation_id / user_message_id / assistant_message_id`；
  - 前端显示失败卡，并提供“重新提问”按钮。
- `client_request_id` 按学生唯一：
  - 重复提交同一个 id 且已有回答 → 返回已保存结果（`deduplicated=true`），不重复生成；
  - 已写入用户消息但回答还没完成 → `409 REQUEST_IN_PROGRESS`；
  - 同一个 id 用于另一个会话 → `409 IDEMPOTENCY_CONFLICT`；
  - 已失败的重放 → 返回 `502`，前端用新 id 重试。

#### 6. 前端操作流程

1. **问答页**顶部新增“新对话 / 历史 / 账号”：
   - 登录后提问自动带令牌；没有当前会话时后端自动创建，并把 `conversation_id` 记到 `store.currentConversationId`；
   - 后续提问带同一个 `conversation_id`，问题和回答自动保存；
   - 游客提问不带令牌，仍不落库；
   - 401 清除登录状态；404 清除当前会话，重新提问会自动建新会话。
2. **历史页**：
   - 登录后显示当前账号的会话列表（标题、最近时间、消息数）；
   - 支持“加载更多”游标分页；
   - 点会话 → `reLaunch` 到问答页并加载该会话的消息；
   - 支持软删除会话；
   - 未登录时显示登录提示，不显示任何会话。
3. **历史消息**：
   - 默认加载最新 50 条，页内按时间正序展示；
   - 顶部有“加载更早的消息”，按游标继续加载；
   - 失败回答显示失败卡和“重新提问”；
   - 打开历史会话后，学习路径页仍可从最近一条有效回答读取路径。
4. **认证页**新增“历史会话”按钮，方便从账号页进入。
