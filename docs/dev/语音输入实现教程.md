# 语音输入实现教程（方案总览）

> 本文是最初的语音输入方案设想与最终实现的对照。**实际实现细节**见：
> [语音识别实现原理](../voice/语音识别实现原理.md)、
> [语音识别配置步骤](../voice/语音识别配置步骤.md)。
> 初版“前端录音 + 服务端 ASR”的方向已落地；本文不再描述“尚未接入”的旧状态。

---

## 1. 目标与完整链路

在聊天输入栏增加麦克风按钮，把口述问题变成文字，填入输入框，由用户校对后再发送。
语音只负责“把话变成字”，不改变知识图谱、检索和问答逻辑。

```text
麦克风 → 录音 → 上传音频 → 后端 /api/transcribe → Qwen-ASR
                                                      ↓ { text }
输入框（用户校对） → 现有 /api/ask → 问答结果
```

---

## 2. 最终实现与初版方案的差异

| 主题 | 初版设想 | 最终实现 |
|---|---|---|
| ASR | 选一个云端 ASR | 阿里云百炼 `qwen3-asr-flash`（OpenAI 兼容） |
| App 录音 | `uni.getRecorderManager()` | 同左，mp3 / 16kHz / 30 秒上限 |
| H5 录音 | 未细化 | `uni.getRecorderManager` 不支持 H5，改用浏览器 `MediaRecorder`；必要时转 16kHz 单声道 WAV |
| 上传 | multipart `file` | 同左；App 传 `filePath`，H5 传 `File` 对象 |
| 识别后 | 填输入框 | 同左，**不自动发送** |
| 音频落盘 | 未规定 | 只读进内存，识别完即丢弃，不写临时文件 |
| 密钥 | 只在后端 | 同左，`ASR_*` 只存在服务器 `.env` |

---

## 3. 关键设计决策

1. **服务端 ASR，而不是浏览器 Web Speech API**：App 与 H5 共用一套逻辑，密钥不进入 APK/H5。
2. **密钥只在后端**：前端只上传音频；后端用 `ASR_API_KEY` 请求百炼，Key 不会被打包进客户端。
3. **Data URL 传输**：Qwen-ASR 的 OpenAI 兼容接口接受 `data:<mime>;base64,<data>`；后端在内存中编码，带真实 MIME。
4. **限制大小与时长**：首版 5MB / 30 秒，前端和后端都校验；空文件、格式不符、超限都有稳定错误码。
5. **不自动发送**：同音字、数字、断句可能出错，必须先让用户校对；用户确认后才走 `/api/ask`。
6. **不保存录音**：识别结束即丢弃；日志不记录 Key、音频内容或转写文本。
7. **HTTPS 是 H5 麦克风的前提**：浏览器要求安全上下文（HTTPS 或 localhost），局域网 HTTP 地址会被拒绝。
8. **APK 权限**：`manifest.json` 声明 `RECORD_AUDIO`，只在用户点麦克风时申请；加权限后必须重新云打包。

## 5. 验收要点

- [ ] 首次点麦克风才申请权限；拒绝后文字输入和问答仍可用。
- [ ] 开始/结束/取消状态明确，重复点击、录音中离开页面不会卡死。
- [ ] 普通话短句能转写并填入输入框，不自动发送。
- [ ] 已有输入时按明确策略追加或提示替换，不静默覆盖。
- [ ] 静音、太短、超时、网络断开、ASR 错误、文件超限都有可理解提示。
- [ ] APK 真机可录音；H5 在 HTTPS 页面可授权并工作。
- [ ] 上传不暴露 ASR 密钥；录音不落盘；日志不含密钥/音频/转写全文。
