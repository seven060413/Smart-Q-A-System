> **文档定位**：把「自律」功能从零接入现有 uni-app 项目；同时记录实现与验证过程，供 AI 编程助手直接照做。

> **范围**：只改 `app/src` 与新增 `app/src/uni_modules`；不改 `src/` 后端、不建数据库表、不改现有问答/登录/语音/视频/历史/学习路径逻辑。

5. **所有颜色/圆角/间距走 `--ik-*` token**，禁止写死 `#2b6cb0`、`#f5f6f8`、`#fff` 等值。token 定义见 `app/src/theme/tokens.js` 和 `docs/设计界面优化.md` 第 4 节。
6. **保持现有代码风格**：`<script setup>`、组合式 API、2 空格缩进、单引号、无分号；新增注释用中文。
7. **每完成一个阶段必须能通过**：

## 1. 目标与非目标

### 1.1 目标

在现有 App 底部导航中加入「自律」tab，顺序固定为 **学习 / 自律 / 我的**，包含：

| 功能 | 说明 |
|---|---|
| 专注计时 | 选任务、选时长、开始、放弃、延长、到点结算点数 |
| 报备 | 选/填目标 App、填写目的与分钟数，到点提醒 |
| 每日打卡 | 每天固定事项、提醒时间、完成/撤销、连续完成 |
| 统计 | 专注分钟、点数变化、打卡完成率、报备按时率、占比、趋势 |
| 提醒 | 专注结束、报备到点、每日打卡；App 后台/被杀也能响 |
| 专注守护 | 专注中离开 App 时，悬浮窗显示原创眼睛 + “我正在看哦” + 剩余时间；点击回到专注 |
| 人格化 | 统一的“它”的文案风格，按事件/结果/严格度取文案 |
| 存储 | 本地持久化，重启不丢；可导出 |

### 1.2 非目标（本阶段明确不做）

- 不读其他 App 的使用时长（不做 UsageStats；v1.1 才考虑可选的“精确前台应用”模式）。
- 不锁屏、不拦截、不阻止用户切 App；悬浮窗只是提醒。
- 不统计“目标 App 实际用了多久”。
- 不做应用限额、不做打开前自动拉起、不做无障碍服务。
- 不做账号同步、不做多端同步。
- 不做 iOS 专项适配（代码不阻止 iOS 编译，但只验证 Android）。
- 不做小程序端。

### 1.3 功能降级说明（必须写进设置页说明）

原“应用限额”改为**自我承诺限额**：报备时填多少分钟，到点提醒；不统计、不阻止。用户需要知道这是“提醒”，不是“强制”。

> 新增的“专注守护”会用到悬浮窗和前台服务。这是为了在离开 App 时仍能显示眼睛；它仍然不是强制拦截——用户可以直接划掉悬浮窗、继续用别的 App。

### 4.2 App 端 SQLite

数据库名 `ikgr_sd`，路径 `_doc/ikgr_sd.db`。

```sql
CREATE TABLE IF NOT EXISTS focus_sessions (
  id TEXT PRIMARY KEY,
  task TEXT NOT NULL,
  planned_min INTEGER NOT NULL,
  actual_min INTEGER NOT NULL DEFAULT 0,
  started_at INTEGER NOT NULL,
  ended_at INTEGER,
  status TEXT NOT NULL,              -- running | completed | abandoned
  points INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS checkin_items (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  note TEXT DEFAULT '',
  remind_time TEXT DEFAULT '',       -- HH:mm，空表示不提醒
  days TEXT NOT NULL DEFAULT '1,2,3,4,5,6,7', -- ISO：1=周一 ... 7=周日
  enabled INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS checkin_records (
  id TEXT PRIMARY KEY,
  item_id TEXT NOT NULL,
  date TEXT NOT NULL,                -- 本地 YYYY-MM-DD
  done_at INTEGER NOT NULL,
  points INTEGER NOT NULL DEFAULT 0,
  UNIQUE(item_id, date)
);

CREATE TABLE IF NOT EXISTS reports (
  id TEXT PRIMARY KEY,
  target_app TEXT NOT NULL,
  purpose TEXT NOT NULL,
  minutes INTEGER NOT NULL,
  started_at INTEGER NOT NULL,
  reminder_at INTEGER NOT NULL,
  ended_at INTEGER,
  status TEXT NOT NULL,              -- active | ended | expired
  points INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS points_ledger (
  id TEXT PRIMARY KEY,
  delta INTEGER NOT NULL,
  reason TEXT NOT NULL,
  ref_type TEXT DEFAULT '',
  ref_id TEXT DEFAULT '',
  created_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS reminders (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,                -- focus | report | checkin
  ref_id TEXT DEFAULT '',
  trigger_at INTEGER NOT NULL,
  title TEXT NOT NULL,
  body TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending' -- pending | fired | cancelled
);

CREATE TABLE IF NOT EXISTS settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_focus_started ON focus_sessions(started_at);
CREATE INDEX IF NOT EXISTS idx_report_started ON reports(started_at);
CREATE INDEX IF NOT EXISTS idx_record_date ON checkin_records(date);
CREATE INDEX IF NOT EXISTS idx_ledger_created ON points_ledger(created_at);
CREATE INDEX IF NOT EXISTS idx_reminder_status ON reminders(status);
```

`plus.sqlite` 用法：

```js
plus.sqlite.openDatabase({ name: 'ikgr_sd', path: '_doc/ikgr_sd.db', success, fail })
plus.sqlite.executeSql({ name: 'ikgr_sd', sql, success, fail })
plus.sqlite.selectSql({ name: 'ikgr_sd', sql, success, fail })
```

注意：`plus.sqlite` 的 `executeSql` / `selectSql` 只接收 SQL 字符串，**不支持参数绑定**。必须封装 `sqlEscape()` 转义单引号，用户输入（任务名、备注、目标 App）一律先转义；`init()` 里的每条 `CREATE` 分开执行，不要一次传多条语句。打卡记录写入用 `INSERT OR REPLACE` 或先查后插，避免 `UNIQUE(item_id, date)` 冲突时抛错。

### 4.3 H5 降级

H5 只用于开发预览：整个库序列化成 JSON 存 `uni.setStorageSync('ikgr_sd_v1', json)`，启动时读入内存，写操作后整体回写。接口与 App 完全一致。不要引入 IndexedDB 增加复杂度。

### 4.4 约定

- `id`：`crypto.randomUUID?.()` 或 `${Date.now()}_${Math.random().toString(36).slice(2, 8)}`。
- 点数只通过 `points_ledger` 计算，**任何地方不得直接改“当前点数”字段**。
- 日期工具放 `dates.js`：`dateKey(ms)`、`startOfDay(ms)`、`endOfDay(ms)`、`addDays(ms, n)`、`weekdayIso(ms)`、`parseHHmm(dateStr, 'HH:mm')`。
- 时区：全部本地时间；中国无夏令时，不做 DST 处理。

## 5. 业务规则

### 5.1 点数账本

| 事件 | reason | delta |
|---|---|---|
| 专注完成 | `focus_complete` | `+planned_min`（1 点/分钟） |
| 专注提前完成 | `focus_early` | `+actual_min`（向下取整） |
| 专注放弃 | `focus_abandon` | `0` |
| 报备完成 | `report_complete` | `+5` |
| 打卡一项 | `checkin` | `+5` |
| 打卡撤销 | `checkin_undo` | `-5` |
| 当日全部打卡 | `checkin_all` | `+5`（每天只记一次） |
| 全部打卡撤销 | `checkin_all_undo` | `-5` |
| 手动调整（设置页，可选） | `manual` | 用户输入 |

- 账本允许负数；当前点数 = `SUM(delta)`，不设下限。
- 撤销打卡必须成对记账，保证统计一致。
- `checkin_all` 用固定 id `checkin_all:<date>` 防重复；撤销时按 id 删除并记反向流水。
- 严格度 A/B 在 v1 **只影响文案**，不影响点数（避免“不检测却扣分”的不公平感）。后续再扩展。

### 5.2 专注状态机

```
idle --start--> running --complete--> completed
                  |  \--extend--> running（planned_min 增加）
                  \--abandon--> abandoned
```

**开始**：

- 任务非空；时长可选 15/25/45/60/90 或自定义 5–180 分钟。
- 若已有 `status='running'` 的会话，弹窗“还有一场专注没结束”，不允许并行。
- 插入 `focus_sessions`；`started_at = Date.now()`；`ended_at = null`。
- 计算 `triggerAt = started_at + planned_min * 60000`；调用 `reminder.scheduleFocus(session)`。
- App 端 `uni.setKeepScreenOn({ keepScreenOn: true })`（仅 `#ifdef APP-PLUS`）。
- 若设置 `guardEnabled !== false`，调用 `guard.startGuard(session)`（悬浮窗 + 前台服务，见 6.8）；启动失败只记录，不阻断专注。

**运行中**：

- 剩余 = `max(0, started_at + planned_min*60000 - now)`，每秒刷新。
- `wd-circle` 显示完成百分比。
- 页面 `onHide` 不停止计时（以时间戳为准）。
- App 进入后台（`App.vue onHide`）→ `guard.onAppBackground()`；回到前台（`onShow`）→ `guard.onAppForeground()`。详见 6.8。

**延长**：

- `planned_min += addMin`；更新记录；`cancel(focus:<id>)` 后重新 schedule；`keepScreenOn` 保持。

**完成**：

- `actual_min = min(planned_min, floor((now - started_at)/60000))`。
- 到点后用户点“完成” → `status='completed'`，points = `planned_min`，写流水 `focus_complete`。
- 未到点但用户点“提前完成” → 二次确认；`status='completed'`，points = `actual_min`，写流水 `focus_early`。
- 取消提醒；`keepScreenOn: false`；`guard.stopGuard()`。

**放弃**：

- 二次确认；`status='abandoned'`；`actual_min` 记录已用时间；points=0；取消提醒；`guard.stopGuard()`。

**恢复**：

- 启动或进入自律页时查 `getRunningFocus()`。
- 若存在：计算剩余；未到点则继续显示；已过点则显示“到点了，待结算”，给“完成/提前完成/放弃”三个选项，不自动结算。
- 若提醒已触发但 App 没开，`reminders` 表状态可能仍是 `pending`；以时间戳判断，不依赖状态。
- 恢复时调用 `guard.reconcile()`：若前台服务还在但专注已结束，停掉服务；若专注仍在进行，服务保持但不主动弹悬浮窗，等下一次 `onHide`。

**统计口径**：

- 专注分钟 = `actual_min` 之和（completed/abandoned 都算实际投入）。
- 完成率 = `status='completed'` 场次 / 已结算场次。
- 放弃场次不计点数。

### 5.3 报备

**创建**：

- 目标 App：预设列表 `微信 / 抖音 / B站 / 游戏 / 浏览器 / 其他`，选“其他”时手输名称。**不读取应用列表**（避免 `QUERY_ALL_PACKAGES` 和额外权限）。
- 目的必填；分钟数 5–180。
- 插入 `reports`，`status='active'`，`reminder_at = started_at + minutes*60000`。
- 调度 `report:<id>`。

**到点**：

- 通知文案：“你报备的 X 分钟到了。” 点击打开 App。
- 报备页/首页显示“待结算”；按钮：
  - **完成了**：`status='ended'`，`ended_at=now`，points=+5，流水 `report_complete`，取消提醒。
  - **再等等我**：`minutes += 5`，`reminder_at += 5*60000`，重新调度。
  - **放弃**：`status='ended'`，points=0，取消提醒。
- 过期未处理：`status='active'` 但 now > reminder_at+5min → UI 标红“已超时”；不自动扣分。下次启动只提示，不自动结束。

**统计口径**：

- 按时率 = `ended` 且 `ended_at <= reminder_at + 5min` 的报备 / 已结束报备。
- 占比按 `target_app` 汇总分钟数。

### 5.4 每日打卡

**事项**：

- 字段：标题、备注、提醒时间（可空）、星期（默认全选）、启用。
- 新增/编辑用 `wd-datetime-picker type="time"` 选 `HH:mm`。
- 删除事项时：同时删除今天以后未触发的 `checkin:<itemId>:*` 提醒；历史记录保留（统计仍算）。

**今日列表**：

- 过滤 `enabled=1` 且 `weekdayIso(today)` 在 `days` 里。
- 每项显示完成状态、备注、提醒时间。
- 点击切换完成：
  - 未完成 → 插入 `checkin_records`（唯一约束 `item_id+date`），+5 流水；取消今天剩余提醒（如果还没响）。
  - 已完成 → 删除记录，-5 流水；若今天已全部完成，再撤销 `checkin_all`。
- 全部完成 → 写 `checkin_all:<date>` +5（只一次）。

**提醒**：

- 每次启动、进入打卡页、增删改事项后，调用 `rescheduleCheckinReminders()`：
  - 为每个启用事项排未来 7 天（今天已过时间的跳过今天）。
  - 提醒 id `checkin:<itemId>:<YYYY-MM-DD>`，`trigger_at` 为当天提醒时间的 epoch ms。
  - 已存在同 id 的先 cancel 再 schedule。
  - 删除不再需要的（事项删除/停用/改时间后的旧 id）。
- 这样即使 App 一周不打开，也能继续提醒。

**统计口径**：

- 完成率 = 区间内已打卡记录数 / 应打卡次数。
- 应打卡次数 = 对区间内每一天，累加当天 `enabled` 且匹配星期的事项数。
- 只统计到“今天”为止，未来日期不计入分母。

### 5.5 统计页口径

范围：近 7 天 / 近 30 天 / 近 90 天（`wd-segmented`）。

| 指标 | 计算 |
|---|---|
| 专注分钟 | 每日 `SUM(actual_min)` |
| 点数净变化 | 每日 `SUM(points_ledger.delta)` |
| 打卡完成率 | 已打卡 / 应打卡（见 5.4） |
| 报备按时率 | 按时结束 / 已结束 |
| 专注任务占比 | 按 `task` 汇总 `actual_min` |
| 报备目标占比 | 按 `target_app` 汇总 `minutes` |
| 趋势 | 选定指标的每日序列 |

实现：仓库层按范围拉原始行，`stats.js` 在 JS 里聚合（数据量小，避免复杂 SQL，也兼容 H5）。空数据显示 `wd-empty`。

### 5.6 严格度

设置项 `strictness: 'A' | 'B'`：

- A 基础：文案温和；B 严格：文案更短、更直接。
- v1 不影响点数、不影响提醒频率。
- 设置页说明：“严格度只改变它说话的方式，不会替你锁应用。”

## 6. 提醒系统与专注守护（原生部分）

### 6.1 能力边界

- `plus.push.createMessage` 的 `delay` 只是“延迟显示”，**进程被杀后不可靠**；只用于 App 存活时的即时提示，不用于“到点提醒”。
- 到点提醒用 **AlarmManager 精确闹钟 + 静态 BroadcastReceiver + NotificationManager**。
- 到点提醒本身不需要前台服务。**只有“专注守护悬浮窗”需要**前台服务 + 悬浮窗权限，且只在专注进行中运行，见 6.8。
- v1 不申请 `PACKAGE_USAGE_STATS`，不读取前台包名；守护触发靠“App 进入后台”事件，因此“打开别的 App”和“回桌面”都会触发。
- 已知限制（必须写进设置页）：
  - 用户在系统设置里“强行停止”App 后，系统会清空闹钟，直到再次打开 App。
  - 个别国产 ROM 可能延迟/拦截闹钟，需要用户允许自启动/省电白名单。

### 6.2 UTS 插件 `ik-reminder`

**行为**：

- `schedule` 先把记录写入 SharedPreferences（key `ik_reminders`，JSON 数组），再设闹钟。
- `cancel` 同时删持久化记录和 PendingIntent。
- 同一 id 重复 schedule：先 cancel 再设，保证只有一条。
- `getScheduled` 返回未来未触发的记录。
- 提醒触发后，receiver 从持久化列表移除该条并更新状态。

**`config.json`**：

平台自带的 `android.app.Notification` / `NotificationManager` / `AlarmManager` 足够，不必引 androidx，避免依赖冲突。

**调度核心（UTS 伪代码，AI 按 UTS 语法补全）**：

```ts
import AlarmManager from 'android.app.AlarmManager'
import PendingIntent from 'android.app.PendingIntent'
import Intent from 'android.content.Intent'
import Context from 'android.content.Context'
import Build from 'android.os.Build'
import { UTSAndroid } from 'io.dcloud.uts'

function setAlarm(id: string, triggerAt: number) {
  const ctx = UTSAndroid.getAppContext()!!
  const am = ctx.getSystemService(Context.ALARM_SERVICE) as AlarmManager
  const intent = new Intent(ctx, ReminderReceiver::class.java) // UTS 写法按实际支持调整
  intent.putExtra('id', id)
  const flags = PendingIntent.FLAG_UPDATE_CURRENT |
    (Build.VERSION.SDK_INT >= 23 ? PendingIntent.FLAG_IMMUTABLE : 0)
  const pi = PendingIntent.getBroadcast(ctx, requestCode(id), intent, flags)

  if (Build.VERSION.SDK_INT >= 31 && !am.canScheduleExactAlarms()) {
    am.setAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, triggerAt, pi)
    return { ok: true, exact: false, reason: 'no-exact-permission' }
  }
  am.setExactAndAllowWhileIdle(AlarmManager.RTC_WAKEUP, triggerAt, pi)
  return { ok: true, exact: true, reason: '' }
}
```

> UTS 里 `ReminderReceiver::class.java` 的写法若不被支持，用 `Intent(ctx, ReminderReceiver::class.java)` 的等价写法或 `new Intent(ctx, ReminderReceiver.class)`；以实际编译结果为准。

**Receiver**：

```ts
import BroadcastReceiver from 'android.content.BroadcastReceiver'
import Context from 'android.content.Context'
import Intent from 'android.content.Intent'

export class ReminderReceiver extends BroadcastReceiver {
  override onReceive(context: Context, intent: Intent) {
    const id = intent.getStringExtra('id') ?? ''
    // 1) 从 SharedPreferences 读出记录，取出 title/body/kind/refId
    // 2) 创建通知渠道（API 26+）
    // 3) 构造 launch PendingIntent：getLaunchIntentForPackage(packageName) + extras
    // 4) NotificationManager.notify(nid, notification)
    // 5) 从持久化列表移除该 id
  }
}
```

**通知渠道**：

| channelId | 名称 | Importance | 用途 |
|---|---|---|---|
| `sd_focus` | 专注结束 | HIGH | 专注到点 |
| `sd_report` | 报备到点 | HIGH | 报备到点 |
| `sd_checkin` | 每日打卡 | DEFAULT | 打卡提醒 |

- 小图标用 `context.getApplicationInfo().icon`；为 0 时用 `android.R.drawable.ic_dialog_info`。
- API 26+：`new NotificationChannel(id, name, importance)` + `createNotificationChannel`。
- API < 26：`Notification.Builder(context)` + `setPriority(PRIORITY_HIGH)` + `setDefaults(DEFAULT_ALL)`。
- `setAutoCancel(true)`；`setContentIntent(launchPi)`。
- 通知 id 用 `id.hashCode() and 0x7fffffff`。

**精确闹钟**：

- Android 12+ 声明 `SCHEDULE_EXACT_ALARM`；Android 14+ 新装默认关闭，必须引导用户去“闹钟和提醒”特殊权限页。
- 未授权时降级 `setAndAllowWhileIdle` / `setWindow`，并在返回值里 `exact=false`，UI 显示“可能延迟几分钟”。
- Doze 下 `setExactAndAllowWhileIdle` 有频率配额（约 9 分钟一次/应用），提醒场景足够。

**开机重排**：

- `BootReceiver` 读 SharedPreferences 中未来时间的记录，逐条重设。
- 过去时间的记录丢弃。
- 注意：BootReceiver 触发时 uni 运行时还没启动，**不能调用任何 uni API**，只能读 SharedPreferences 和发通知/设闹钟。

**通知点击**：

- v1 简化：点击只打开 App，不深度路由。
- 用 `context.getPackageManager().getLaunchIntentForPackage(context.getPackageName())` 生成 Intent，加 `FLAG_ACTIVITY_NEW_TASK`；可选 extras `sd_kind`/`sd_ref_id` 供 v1.1 使用。
- 进入 App 后，自律首页根据数据库里的 `running focus` / `active report` 显示“待结算”卡片，不依赖 intent extras。

### 6.4 JS 调度层

`reminder.js` 统一入口，页面不直接调 UTS：

```js
// 条件编译：H5 不 import 原生模块
// #ifdef APP-PLUS
import * as native from '@/uni_modules/ik-reminder'
// #endif

export async function scheduleFocus(session) { ... }
export async function scheduleReport(report) { ... }
export async function scheduleCheckinReminders(items) { ... }
export async function cancelReminder(id) { ... }
export async function reconcile() { ... }
export async function getReadiness() { ... }
```

**幂等与对账**：

- `scheduleFocus`：id `focus:<sessionId>`；先 `cancelReminder('focus:<id>')` 再 schedule；同时写 `reminders` 表。
- `scheduleReport`：id `report:<id>`；同上。
- `scheduleCheckinReminders`：生成未来 7 天 id 集合；对比 `reminders` 表里 `kind='checkin'` 的 pending 记录，取消多余的，补排缺少的。
- `reconcile()`：启动时调用；读 `reminders` pending 列表与原生 `getScheduled()`，双向补齐/清理。
- 提醒触发后不要求 JS 立即更新；下次启动 `reconcile()` 会把已过时间的记录标 `fired` 或删除。

**H5 降级**：

- `reminder-web.js`：用 `setTimeout` + `Notification`（页面开着才有效）；`getStatus()` 返回 `supported:false`。
- H5 页面显示“网页版仅在页面打开时提醒；完整提醒请用安卓 App”。

### 6.5 权限流程

**通知权限（Android 13+）**：

- JS 调 `plus.android.requestPermissions(['android.permission.POST_NOTIFICATIONS'], ...)`。
- 结果 `granted`/`denied`；拒绝后按钮变“去设置开启”，调 `native.openNotificationSettings()`。
- 插件 `getStatus().notifications` 必须反映真实状态。

**精确闹钟（Android 12+）**：

- `native.canScheduleExactAlarms()`；false 时显示“去开启”，调 `native.openExactAlarmSettings()`。
- Android 14+ 必须由用户手动开；不能假设已授权。

**开机自启**：

- `RECEIVE_BOOT_COMPLETED` 是普通权限，不用运行时申请。
- 国产 ROM 的“自启动”是厂商设置，无法用 API 打开；权限页给文字指引。

**电池优化**（可选，不强制）：

- 只显示状态和建议，不主动申请 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`；避免商店审核和用户反感。

### 6.6 生命周期与边界

| 场景 | 预期 |
|---|---|
| App 前台 | 通知正常；也显示应用内提示 |
| App 后台 | 通知正常 |
| App 被划掉（最近任务） | 通知正常（静态 receiver） |
| 重启手机 | BootReceiver 重排，通知正常 |
| 用户“强行停止” | 闹钟被系统清空，直到再次打开 App；UI 明示 |
| 拒绝通知权限 | 无通知；权限页红字提示 |
| 拒绝精确闹钟 | 降级，可能延迟几分钟；UI 明示 |
| 修改系统时间/时区 | v1 不处理；下次打开 App 时 `reconcile()` 纠正 |
| 同一提醒延长 | 先 cancel 再 schedule，不能重复响 |
| 删除打卡事项 | 取消该事项未来提醒，历史记录保留 |
| 专注中切到别的 App | 1.5 秒宽限后显示守护悬浮窗；回到 App 隐藏 |
| 专注中锁屏 | 悬浮窗不覆盖锁屏；解锁后按服务状态恢复 |
| 专注中强行停止 | 服务/悬浮窗消失；重开 App 后按数据库状态恢复 |
| 悬浮窗权限被拒 | 不显示悬浮窗；到点通知仍正常，权限页红字提示 |

### 6.7 备选方案（M0 失败时）

按优先级：

1. **市场 UTS 插件**：`hans-local-notify`（DCloud 插件市场 id 29887，<https://ext.dcloud.net.cn/plugin?id=29887>）、`hy-notification`（id 30151，<https://ext.dcloud.net.cn/plugin?id=30151>）。它们覆盖定时通知、持久化、开机重排、精确闹钟降级。用之前先看它的 API/授权/维护状态；用适配层包住，页面不直接依赖。
2. **传统 Android 原生插件 + 离线打包**：写 Kotlin `AlarmManager` + receiver，接入 DCloud 离线 SDK。最稳，但打包链更重。
3. **不推荐**：纯 `plus.push.createMessage` + 前端定时器。App 被杀就失效，不能作为正式方案。

### 6.8 专注守护（悬浮窗 + 前台服务）

> **需求**：专注进行中，如果用户切到别的 App，浮现一个原创眼睛悬浮窗，并提示“我正在看哦”。
> **参考站对照**：`im-watching-u.kkeist.com` 的原生能力清单里有 `overlay / serviceRunning / usage / exactAlarm / battery` 等字段，说明它也是原生层实现悬浮窗和前台服务。我们只借鉴“被它看着”的交互概念，**不复制它的代码、图形、动画和文案**。v1 不申请 `PACKAGE_USAGE_STATS`，靠 App 进入后台触发。

| 维度 | 参考站 | 本方案 v1 |
|---|---|---|
| 检测 | 原生层有 `usage / recentApps` 等能力，能判断前台应用 | `App.vue onHide`，不读前台包名 |
| 悬浮窗 | 原生 overlay | 原生 overlay（`TYPE_APPLICATION_OVERLAY`） |
| 眼睛视觉 | 其自有素材 | 原创几何杏仁眼（7.3） |
| 强度 | 可报备、可严格模式 | 只提醒，可直接忽略/划走 |
| 权限 | 使用情况、悬浮窗等 | 悬浮窗 + 前台服务 + 通知；不申请使用情况 |

#### 6.8.1 触发与检测

- 触发点：`App.vue` 的 `onHide`。如果当前有 `running` 专注且 `settings.guardEnabled !== false`，调用 `guard.onAppBackground()`。
- 取消点：`App.vue` 的 `onShow` 调用 `guard.onAppForeground()`，隐藏悬浮窗。
- **1.5 秒宽限**：`onHide` 后 1.5 秒内回到 App（误触、通知栏下拉）不显示，避免闪烁。
- v1 不读前台包名，因此“打开别的 App”“回桌面”“打开最近任务”都会触发。这是已知边界，设置页写明。
- 可选 v1.1“精确模式”：前台服务里用 `UsageStatsManager` 轮询前台包名，只在前台不是本 App 时显示；需要 `PACKAGE_USAGE_STATS`，默认关闭，单独开关 + 权限引导。
- 只允许一个守护实例；重复 `onHide` 复用现有悬浮窗。
- 专注结束/放弃时 `guard.stopGuard()`；服务停止、悬浮窗移除。
- 已知误触发：下拉通知栏、系统权限弹窗、分屏切换也可能触发 `onHide`。1.5 秒宽限 + `onShow` 会收回大部分；若仍频繁误弹，v1.1 用“前台包名检测”或 `PowerManager.isInteractive` 过滤。

#### 6.8.2 UTS 插件 `ik-guard`

目录与 `ik-reminder` 相同（`uni_modules/ik-guard/utssdk/app-android`）。API：

```ts

export function hasOverlayPermission(): boolean
```

- `guard.js` 包一层，页面/`App.vue` 不直接 import UTS。
- `state`：`focus | due | snooze`，对应眼睛状态。
- 所有调用要在 `#ifdef APP-PLUS` 下；H5 空实现。

#### 6.8.3 前台服务

- 类：`FocusGuardService extends Service`，`START_STICKY`。
- 专注开始且 App 在前台时启动：`startForegroundService`；服务立刻 `startForeground`。
- 通知渠道 `sd_guard`：名称“专注守护中”，importance `LOW`，`ongoing=true`，内容“专注中 · 还剩 12:34”；点击打开 App。
- 专注完成/放弃：`stopForeground(STOP_FOREGROUND_REMOVE)` + `stopSelf()`。
- Android 14+：manifest 声明 `android:foregroundServiceType="specialUse"`，并加：
  ```xml
  <property
    android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE"
    android:value="focus_guard"/>
  ```
  权限：`FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE`。
- 启动失败（Android 12+ 后台启动限制、厂商拦截）：捕获异常，`getStatus().serviceRunning=false`，降级为“只有到点通知”；不阻断专注。
- 服务被系统杀掉后 `START_STICKY` 重启；从 SharedPreferences 读 `guardState`，若专注仍在进行且 `overlayRequested=true`，重新显示。

#### 6.8.4 悬浮窗

**权限**：

- `SYSTEM_ALERT_WINDOW`；`Settings.canDrawOverlays(context)` 检查。
- 跳转：`Settings.ACTION_MANAGE_OVERLAY_PERMISSION` + `Uri.parse("package:" + packageName)`。
- 未授权：专注照常，只是不显示悬浮窗；权限页红字“悬浮窗未开启，离开 App 时只会收到通知”。

**窗口参数**：

- API 26+：`WindowManager.LayoutParams.TYPE_APPLICATION_OVERLAY`；API <26：`TYPE_PHONE`。
- Flags：`FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL | FLAG_LAYOUT_IN_SCREEN`。
- Format：`PixelFormat.TRANSLUCENT`。
- Gravity：`TOP | END`；x/y 边距 16dp；y 从状态栏下开始。
- 不添加全屏 dim、不拦截卡片外的触摸。

**两种形态**：

| 形态 | 尺寸 | 内容 | 行为 |
|---|---|---|---|
| 气泡 | 64dp 圆角方块 | 眼睛 40×24dp | 默认收起态；点击展开 |
| 卡片 | 280dp 宽 | 眼睛 96×56dp + 标题 + 副标题 + 按钮 | 首次出现时展开；5 秒后自动收成气泡 |

**卡片内容**：

```
[眼睛]
我正在看哦
专注还剩 12:34 · 数学作业
[回到专注]  [5 分钟后再提醒]
```

- 标题候选（原创，轮换）：`我正在看哦` / `看见你了` / `别走太远`。
- 副标题：`专注还剩 {mm:ss} · {task}`；任务为空时只显示时间。
- 到点：眼睛切 `due`，标题“时间到了”，副标题“回来结算”，按钮“回到专注”。
- 气泡位置固定在右上角；v1 不做拖动，减少触摸冲突。
- 出现动画：scale 0.86→1 + alpha 0→1，220ms；收起 180ms。

**按钮动作**：

- `回到专注`：`getLaunchIntentForPackage` + `FLAG_ACTIVITY_NEW_TASK` 打开 App；App `onShow` 后悬浮窗消失。
- `5 分钟后再提醒`：隐藏悬浮窗；服务用 `Handler.postDelayed` 5 分钟后再判断：App 仍在后台且专注未结束 → 再次显示；否则不显示。
- **不在悬浮窗里直接“结束专注”**，避免误触丢点数；结束必须回 App 二次确认。

#### 6.8.5 原生眼睛 `EyeView`

- `EyeView extends View`，`onDraw(Canvas)` 绘制；尺寸 96×56dp（卡片）/ 40×24dp（气泡）。
- 几何比例与 Vue `EyeGaze` 一致：单眼宽 32dp、高 22dp、间距 6dp；虹膜 13dp；瞳孔 6dp；高光 2.5dp。
- 固定深色调色板（悬浮窗始终是深色卡片，不跟随 App 主题）：
  - 眼白 `#F4F1EA`
  - 虹膜 `#5B9BD5`
  - 瞳孔 `#14161A`
  - 高光 `#FFFFFF`
  - 眼皮/遮罩 `#1F2937`
- 状态：
  - `focus`：睁大；瞳孔按剩余时间绕小圆偏移，每秒更新。
  - `due`：放大 1.12 倍；外圈脉冲（半透明圆环）。
  - `snooze`：半闭眼，瞳孔居中。
- 眨眼：`ValueAnimator` 0→1→0，160ms；`Handler` 每 4–7 秒触发；`focus` 状态降到 8–12 秒。
- `contentDescription`：`它正在看着你`；不要只靠眼睛传递信息。

#### 6.8.6 与“不做强制拦截”的边界

- 悬浮窗只占卡片区域，不遮全屏、不拦截点击；用户可以直接忽略或划走。
- 不读使用时长、不限制 App、不自动拉起目标 App、不锁屏。
- 前台服务的常驻通知是 Android 的硬性要求，不是“监控”；设置页说明用途。
- 隐私：不截图、不拍照、不读通知内容；只保存 `focusId/endAt/task` 和显示状态。

#### 6.8.7 失败与降级

| 情况 | 行为 |
|---|---|
| 悬浮窗权限拒绝 | 不显示悬浮窗；到点通知正常；权限页提示 |
| 通知权限拒绝 | 前台服务通知不可见（系统仍要求服务有通知）；悬浮窗权限若已给仍可显示 |
| 前台服务启动失败 | 捕获异常；降级为纯通知；记录 `serviceRunning=false` |
| 厂商杀服务 | `START_STICKY` 重启；重启后按持久化状态决定是否恢复悬浮窗 |
| 用户从最近任务划掉 App | `onHide` 可能来不及；悬浮窗可能不出现；重开 App 后按数据库恢复专注 |
| “5 分钟后再提醒”期间进程被杀 | 不会自动再提醒；回 App 后按专注状态恢复 |
| 用户强行停止 | 服务/悬浮窗全部停止；重开 App 后恢复专注状态 |
| 锁屏 | 悬浮窗不覆盖锁屏；解锁后若仍在后台，按状态恢复 |
| 到点时在别的 App | 守护悬浮窗切 `due` + 到点通知；回 App 结算 |

#### 6.8.8 权限清单（专注守护新增）

```xml
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE"/>
<uses-permission android:name="android.permission.VIBRATE"/>
```

- `POST_NOTIFICATIONS` 已在提醒插件声明。
- **不加** `PACKAGE_USAGE_STATS`（v1）、`BIND_ACCESSIBILITY_SERVICE`、`QUERY_ALL_PACKAGES`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。
- 上架商店时，悬浮窗 + 前台服务属于重点审查项；只发 APK 风险较低。

### 7.3 原创眼睛组件 `EyeGaze`

> **原创声明**：只保留“被它看着”的概念。参考站的眼睛形状、颜色、动画、素材一律不复制。我们的设计语言是**对称杏仁眼 + 进度瞳孔 + 无睫毛 + 单点高光**，全部用 CSS/view 绘制，不引入图片。

#### 7.3.1 设计语言

- 两只对称的杏仁眼，没有脸、没有嘴、没有睫毛；极简、冷静、略带压迫感。
- 情绪只由三件事表达：**眼皮开合、瞳孔偏移、整体缩放**。
- 颜色全部来自 token；人格卡上用 `on-block` 调色。
- 不用卡通高光、血丝、渐变虹膜等参考站可能有的元素。

#### 7.3.2 几何规格（Vue，rpx）

| 项 | 值 |
|---|---|
| 根节点 | 180 × 110 rpx |
| 单眼 | 64 × 44 rpx |
| 双眼间距 | 24 rpx |
| 虹膜 | 26 rpx |
| 瞳孔 | 12 rpx |
| 高光 | 5 rpx，左上偏移 4/3 rpx |
| 眨眼 | 160 ms，`scaleY 0→1→0` |
| 视线偏移 | 最大 ±8 rpx X、±5 rpx Y |
| 到点放大 | 1.12 倍 |
| 半闭（snooze） | `scaleY .55` |
| 眯眼（done） | `scaleY .45` |

```
        ┌──────────────────────────┐
        │    ◉            ◉        │   单眼 64×44rpx
        │  虹膜26  瞳孔12  高光5   │
        └──────────────────────────┘
```

#### 7.3.3 组件 API

```js
<EyeGaze
  state="idle"        // idle | focus | abandon | done | due | snooze
  :progress="0.62"    // 0–1，仅 focus 用；瞳孔绕小圆跟随倒计时
  :size="180"         // rpx，默认 180
  :on-block="true"    // 放在 --ik-block 人格卡上时传 true
  :reduced-motion="false"
/>
```

| prop | 类型 | 默认 | 说明 |
|---|---|---|---|
| `state` | String | `idle` | 状态 |
| `progress` | Number | `1` | 剩余比例；focus 时计算视线角度 |
| `size` | Number | `180` | 根节点宽度（rpx），高度按 110/180 比例 |
| `onBlock` | Boolean | `false` | 使用 on-block 调色 |
| `reducedMotion` | Boolean | `false` | 关闭眨眼/视线动画 |

不 emit 事件；纯展示组件。

#### 7.3.5 视线计算（focus）

```js
const gaze = computed(() => {
  if (state.value !== 'focus') return { x: 0, y: 0 }
  const p = Math.min(1, Math.max(0, progress.value))
  const angle = (1 - p) * Math.PI * 2 - Math.PI / 2
  return {
    x: Math.cos(angle) * 8,   // rpx
    y: Math.sin(angle) * 5,   // rpx
  }
})
const irisStyle = computed(() => ({
  '--gaze-x': `${gaze.value.x}rpx`,
  '--gaze-y': `${gaze.value.y}rpx`,
}))
```

- 剩余 100% 时瞳孔在正上方，随时间顺时针绕一个小圆；到 0% 回到正上方。
- `transition: transform .8s linear` 让每秒更新看起来是连续移动。
- 如果不想绕圈，可改成按剩余时间左右摆动（±6rpx），也符合“跟随倒计时”。

#### 7.3.6 状态与动画

| state | 触发 | 眼睛 | 动画 |
|---|---|---|---|
| `idle` | 无专注、日常 | 70–100% 睁开，瞳孔居中 | 每 4–7s 缓慢眨眼 160ms |
| `focus` | 专注进行中（App 内） | 100% 睁开，瞳孔跟随倒计时 | 每 8–12s 眨眼；视线平滑移动 |
| `abandon` | 放弃后 1.5s | 半闭，瞳孔看向一侧 | 0.35s 过渡，然后回 idle |
| `done` | 专注完成 / 全部打卡 | 眯眼，瞳孔略上移 | 0.35s 收起 |
| `due` | 专注到点 | 睁大 1.12 倍，瞳孔居中 | 外圈脉冲 1.4s 循环 |
| `snooze` | 悬浮窗“5 分钟后再提醒” | 半闭，瞳孔居中 | 静止 |

- 眨眼定时器只保留一个；`onUnmounted` 清理。
- `reducedMotion=true` 或 H5 `prefers-reduced-motion: reduce` 时：不眨眼、不做视线过渡、不脉冲，只保留静态状态。

#### 7.3.7 无障碍

`aria-label` 映射：

| state | label |
|---|---|
| idle | 它安静地看着 |
| focus | 它正在看着你的专注 |
| abandon | 它把视线移开了 |
| done | 它眯起了眼睛 |
| due | 它睁大了眼睛，时间到了 |
| snooze | 它半闭着眼，在等你 |

- 眼睛只是装饰/情绪，不能作为唯一信息源；剩余时间、点数等必须有文字。
- 不用 `aria-hidden`，让读屏能读到状态。

#### 7.3.8 原生悬浮窗里的同一双眼睛

Vue 组件不能渲染到别的 App 上，悬浮窗必须用 UTS 原生 `Canvas` 重画。规格见 6.8.5；要点：

- 几何比例与 7.3.2 完全一致，按 dp 缩放：单眼 32×22dp，虹膜 13dp，瞳孔 6dp，高光 2.5dp。
- 固定深色调色板（不跟随 App 主题）：眼白 `#F4F1EA`、虹膜 `#5B9BD5`、瞳孔 `#14161A`、高光 `#FFFFFF`、眼皮 `#1F2937`。
- 状态与动画与 Vue 版一一对应；`focus/due/snooze` 三种够用。
- 手势/按钮在原生层处理，不经过 Vue。

#### 7.3.9 使用位置

| 位置 | 状态 |
|---|---|
| 首页人格卡 | `idle`；有专注时 `focus`；到点 `due`；完成 `done`；放弃后短暂 `abandon` |
| 专注页 | `focus`；到点 `due` |
| 专注结算卡 | `done` |
| 悬浮窗（原生） | `focus` / `due` / `snooze` |
| 通知图标 | 不用眼睛，用应用图标（避免通知栏小图看不清） |

## 8. 页面规格

所有页面根节点：

```vue
<view class="sd-page theme-root" :class="{ 'is-dark': isDark }" :style="themeVars">
```

- 所有卡片背景 `var(--ik-card)`、圆角 `var(--ik-radius)`、主文字 `var(--ik-t1)`、次文字 `var(--ik-t2)`。

### 8.2 专注页 `focus.vue`

两种状态：

1. **未开始**：任务输入、时长分段（15/25/45/60/90/自定义）、开始按钮、人格文案 + `EyeGaze state="idle"`。
2. **进行中**：`EyeGaze state="focus" :progress="remainingRatio"` + `wd-circle` 大圆环 + 剩余时间、任务名、[延长 10 分钟] [提前完成] [放弃]。
3. **待结算**：到点后 `EyeGaze state="due"`，显示三个按钮。

- 提前完成/放弃必须 `uni.showModal` 二次确认。

- 专注页 `onHide` 不主动弹悬浮窗（由 `App.vue` 统一触发），避免页面和全局逻辑重复。

### 8.3 报备页 `report.vue`

### 8.4 打卡页 `checkin.vue`

- 底部 [+ 添加事项]；事项管理：编辑/删除/启用开关/星期选择/提醒时间。

### 8.5 统计页 `stats.vue`

- 空态：所选范围无数据。

### 8.6 设置页 `settings.vue`

- 提醒权限状态卡：通知/精确闹钟/开机重排，每项显示“已开启/未开启/不支持”，点击跳权限页。

- 数据：今日点数、总记录数、导出 JSON 到剪贴板（可选）、清空数据（二次确认）。
- 关于：版本、提醒能力说明、限制说明。

### 8.7 权限页 `permissions.vue`

逐项：

| 项 | 状态来源 | 操作 |
|---|---|---|
| 通知权限 | `ik-reminder.getStatus().notifications` | 申请 / 去设置 |
| 精确闹钟 | `canScheduleExactAlarms()` | 去开启 |
| 悬浮窗 | `ik-guard.getStatus().overlay` | 去开启 |
| 前台服务通知 | `ik-guard.getStatus().serviceRunning` / 通知渠道存在 | 文字说明 |
| 开机重排 | 静态权限，恒为“已声明” | 文字说明 |
| 电池优化 | 可选，只显示建议 | 文字说明 |
| 厂商自启动 | 无法检测 | 文字说明 + 手动步骤 |
| 精确前台应用（v1.1 可选） | `ik-guard.getStatus().usage` | 默认关闭；开启时才引导 |

- 每次 `onShow` 重新读状态。
- 不支持/未授权的项用 `--ik-danger` 标注“未开启”，但不要阻止用户继续用专注。
- 不支持的平台（H5）显示“网页版仅页面内提醒，不支持悬浮窗”。

```js
// #ifdef APP-PLUS
import { currentFocusSession, onAppBackground, onAppForeground, reconcileGuard } from './selfdiscipline/guard.js'
// #endif

export default {
  onShow() {
    // #ifdef APP-PLUS
    onAppForeground()
    reconcileGuard()
    // #endif
  },
  onHide() {
    // #ifdef APP-PLUS
    if (currentFocusSession()) onAppBackground() // 同步读内存，不要 await 数据库
```

## 11. 实验过程（提醒 + 悬浮窗验证手册）

> 目标：在写任何业务页面之前，先证明两件事：
> 1. **M0**：App 被杀、锁屏、重启后仍能到点通知。
> 2. **M4 前置**：专注中离开 App 后能盖出眼睛悬浮窗，回到 App 能消失。
>
> 这两步失败，后面全部白做。

### 11.1 准备

1. 手机：Android 10–15 真机一台（最好再准备一台国产 ROM，如 MIUI/HyperOS、ColorOS）。
2. HBuilderX 4.41+，项目根目录 `D:\IKGR-system-eands\app`。
3. 打开 USB 调试；`adb devices` 能看到设备。
4. 新建 UTS 插件骨架，写入第 6 节的 manifest 和最小实现。
5. HBuilderX：**运行 → 运行到手机或模拟器 → 制作自定义调试基座**（标准基座不含新增 receiver/权限，必须自定义）。
6. 安装自定义基座后，再“运行到手机”。

### 11.2 实验 A：60 秒提醒（前台）

1. App 打开，进入临时调试页。
2. 点“60 秒后提醒”，授予通知权限。
3. 保持 App 前台，等待。
4. **预期**：60 秒 ±5 秒内出现通知，标题/正文正确，声音/震动按渠道。

记录：实际延迟 = 通知出现时间 − 点击时间。

### 11.3 实验 B：杀进程 + 锁屏

1. 点“10 分钟后提醒”。
2. 从最近任务划掉 App。
3. 锁屏，等待 10 分钟。
4. **预期**：通知准时出现；点击通知能打开 App。
5. 再重复一次“划掉 + 不锁屏”。

### 11.4 实验 C：重启

1. 点“15 分钟后提醒”。
2. 重启手机（不要打开 App）。
3. 等待 15 分钟。
4. **预期**：通知准时出现（BootReceiver 重排成功）。
5. 若失败：检查 `RECEIVE_BOOT_COMPLETED` 是否声明、BootReceiver 是否 `exported="true"`、ROM 是否禁止自启动。

### 11.5 实验 D：拒绝权限

1. 系统设置里关闭该 App 的通知权限；点“60 秒后提醒”。
2. **预期**：到点无通知；App 内 `getStatus().notifications=false`，权限页红字提示。
3. 关闭“闹钟和提醒”特殊权限（Android 12+）；再点。
4. **预期**：`exact=false`，仍能提醒但可能延迟；UI 提示“可能延迟几分钟”。

### 11.6 实验 E：取消/延长/重复

1. 点“10 分钟后提醒”，再点“取消”。
2. **预期**：到点不响。
3. 点“10 分钟后提醒”，5 分钟时点“延长 5 分钟”。
4. **预期**：只在延长后的时间响一次，不重复。
5. 同一 id 连续 schedule 两次。
6. **预期**：只有一条通知。

### 11.7 实验 F：强行停止（记录限制，不要求通过）

1. 系统设置 → 应用 → 强行停止。
2. 点过的提醒到点。
3. **预期**：不响；这是 Android 机制。
4. 打开 App 后 `reconcile()` 应把过期提醒标为 `fired`/删除，并重新排未来的。

### 11.8 故障排查

```powershell
adb shell dumpsys alarm | findstr ikgr
adb shell dumpsys notification --noredact | findstr ikgr
adb shell dumpsys activity services | findstr ikgr
adb shell appops get com.your.package SYSTEM_ALERT_WINDOW
adb logcat -s ik-reminder:* ik-guard:* AndroidRuntime:E
```

检查：

- receiver 的完整类名是否与构建产物一致。
- `android:exported` 是否正确。
- 通知渠道是否创建；Android 13+ 是否授权。
- `setExactAndAllowWhileIdle` 是否抛 `SecurityException`（精确闹钟权限）。
- 电池优化/自启动是否拦截（国产 ROM）。
- 悬浮窗：`SYSTEM_ALERT_WINDOW` appop 是否 allow；服务是否在运行；`WindowManager` 是否 add 成功。

### 11.9 实验 G：专注守护悬浮窗（M4 前置烟测）

> 目标：先证明“离开 App 后能盖出眼睛卡片”，再写 EyeGaze 的完整状态。

**准备**：

1. 在 UTS 插件 `ik-guard` 里放临时按钮：`开始守护` / `停止守护` / `检查权限`。
2. 授权：设置 → 应用 → 特殊权限 → 显示在其他应用上层 → 允许。
3. 通知权限允许；Android 14 确认前台服务类型声明正确。
4. 用自定义基座运行。

**用例**：

| 编号 | 步骤 | 预期 |
|---|---|---|
| G1 | 开始专注 → 按 Home | 1.5 秒后右上角出现卡片：眼睛 + “我正在看哦” + 剩余时间 |
| G2 | 从桌面打开微信 | 悬浮窗仍在；眼睛眨眼；卡片不遮全屏 |

| G4 | 点“5 分钟后再提醒” | 悬浮窗消失；5 分钟后若仍在别的 App 且专注未结束，再次出现 |

**失败排查**：

- 没出现：检查 `Settings.canDrawOverlays`、WindowManager.addView 异常、服务是否 `startForeground`。
- 出现后马上消失：检查 `onAppForeground` 是否被误触发；1.5 秒宽限是否取消。
- 服务被杀：检查 `START_STICKY`、电池优化、厂商自启动。
- Android 14 崩溃：检查 `foregroundServiceType` 和 `<property>`。

## 14. 风险与回退

| 风险 | 影响 | 应对 |
|---|---|---|
| UTS 静态 receiver 类名/注册不生效 | 杀进程后不提醒 | 按构建产物改 manifest；仍失败则换市场插件或传统原生插件 |
| 自定义基座打包失败 | 无法真机验证 | 先只放权限/空 receiver 验证打包；再逐步加逻辑 |
| 国产 ROM 拦闹钟 | 延迟/不响 | 权限页给自启动/省电指引；不承诺 100% |
| 用户强行停止 | 闹钟清空 | 文档/UI 明确说明 |
| Android 14 精确闹钟默认关闭 | 延迟 | 引导 + 降级 + `exact=false` 提示 |
| plus.sqlite 在部分设备异常 | 数据读写失败 | 捕获异常，降级到 `uni.setStorageSync` JSON；设置页显示存储模式 |
| 账本/记录不一致 | 统计错误 | 所有增减只走 `addLedger`；撤销成对；定期用 `sumPoints()` 校验 |
| 通知小图标缺失 | 通知不显示/白块 | 使用应用 icon；为 0 时用系统图标 |
| 悬浮窗权限被拒/厂商拦截 | 离开 App 不显示眼睛 | 降级为通知；权限页红字引导；不阻断专注 |
| 前台服务被 ROM 杀掉 | 悬浮窗消失 | `START_STICKY` + 状态持久化；自启动指引；不承诺 100% |
| Android 14 前台服务类型错误 | 启动崩溃 | `specialUse` + `<property>`；真机验证 |
| 悬浮窗遮挡/打扰 | 用户体验差 | 只占右上角卡片；5 秒收起；可关闭 `guardEnabled` |
| 原生 EyeView 与 Vue 版不一致 | 视觉割裂 | 共用 7.3.2 比例；截图对比；先做 G1 烟测 |
| 悬浮窗 + 前台服务商店审核 | 上架受阻 | 只发 APK 风险低；上架需说明用途 |
| 复制参考站文案/资源 | 版权风险 | 全部原创；代码不参考其压缩包 |

## 附录 F：AI 事项整理（P1 + P2，2026-11-21）

### F.1 产品行为

- 入口：自律首页「今日事项」卡片中的 **AI 助手**（只保留一个入口），点击后 `uni.navigateTo` 进入独立聊天页 `pages/selfdiscipline/assistant`。
- 交互：聊天式界面，用户消息在右、助手消息在左；底部输入框支持 **文字** 与 **语音转文字**（App 原生录音 / H5 MediaRecorder，识别后放入输入框，可编辑后发送）。
- 流程：发送一句话 → 后端解析 → 助手消息中出现 **事项预览卡**（标题、重复方式、提醒时间可编辑）→ 用户点「添加到今日事项」→ 写入本地，并追加一条已加入的助手消息。
- 非创建意图：用户说「不用了 / 算了 / 取消 / 这个先放着吧 / 谢谢」等，**不会生成事项**。前端对常见取消/闲聊短语直接短路；其他说法由后端模型返回 `items: []` + `intent`，前端只显示助手回复。若已有未确认的预览卡，取消语句会把它撤销。
- 聊天记录仅保留在当前页面会话内；离开页面后重新进入从欢迎语开始。
- 重复规则（产品决策）：
  - 句子里有「每天 / 每日 / 天天」→ 每日重复；
  - 「工作日」→ 周一至周五；「周末」→ 周六周日；
  - 「每周一 / 周三」→ 指定星期重复；
  - 其他情况 → **仅今天一次**。
- 截止时间（如「10 点前交」）：提醒设为截止前 30 分钟，note 写明截止时间。
- AI 只负责整理，不直接写库；确认后才创建，避免误建提醒。
- 手动添加仍完整保留，游客可手动使用；AI 整理必须登录。

### F.2 接口

```http
POST /api/selfdiscipline/parse-items
Authorization: Bearer <token>
Content-Type: application/json

{
  "text": "每天9点背20个单词；今天下午6点交数学作业",
  "today": "2026-11-21",
  "weekday": 6,
  "now": "15:30",
  "timezone": "Asia/Shanghai",
  "client_request_id": "..."
}
```

返回：

```json
{
  "items": [
    {
      "title": "背单词",
      "note": "20个",
      "kind": "daily",
      "days": [1, 2, 3, 4, 5, 6, 7],
      "date": "",
      "remind_time": "09:00",
      "enabled": true,
      "confidence": 0.9
    },
    {
      "title": "交数学作业",
      "note": "截止时间：18:00",
      "kind": "once",
      "days": [],
      "date": "2026-11-21",
      "remind_time": "17:30",
      "enabled": true,
      "confidence": 0.9
    }
  ],
  "reply": "整理好了",
  "source": "ai",
  "intent": "create"
}
```

- `intent`：`create` 创建事项；`cancel` 取消/拒绝；`chat` 闲聊；`clarify` 需要追问。非 `create` 时 `items` 为空数组，前端不显示预览卡、不显示错误。

- 必须登录（`get_auth_context`）。
- 按用户限流：默认 10 分钟 20 次（`SD_PARSE_RATE_LIMIT` / `SD_PARSE_RATE_WINDOW_SECONDS`）。
- 服务端再次校验：标题长度、`HH:mm`、星期 1–7、日期范围、最多 20 项、去重。
- 模型不可用/限流/超时：返回本地规则结果，`source` 为 `local`，前端提示“离线规则整理，请检查”。

### F.3 模型配置

优先使用 OpenAI 兼容环境变量：

```env
SD_PARSE_API_KEY=...
SD_PARSE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
SD_PARSE_MODEL=qwen-flash
SD_PARSE_TIMEOUT_SECONDS=8
```

- 未设置 `SD_PARSE_*` 时回退到 `QWEN_API_KEY` / `QWEN_BASE_URL` / `DASHSCOPE_API_KEY`。
- 默认 `qwen-flash`：短 JSON 解析实测约 **2 秒**；`qwen-turbo` 在当前账号下出现 `RateLimitError`，不作为默认值。
- 切换 DeepSeek 只需改环境变量，不改代码：
  ```env
  SD_PARSE_BASE_URL=https://api.deepseek.com/v1
  SD_PARSE_API_KEY=...
  SD_PARSE_MODEL=deepseek-chat
  ```

### F.4 数据模型与提醒

- `checkin_items` 增加：
  - `kind TEXT NOT NULL DEFAULT 'daily'`：`daily` 每日重复 / `once` 仅一次；
  - `date TEXT DEFAULT ''`：一次性事项的本地日期 `YYYY-MM-DD`。
- H5 JSON 旧数据自动按 `daily` 处理；App SQLite 启动时执行 `ALTER TABLE`，列已存在则忽略。
- 提醒：
  - `daily`：未来 7 天滚动排期；
  - `once`：只在 `date + remind_time` 排一次；
  - 提醒 id 仍为 `checkin:<itemId>:<date>`。
- 统计：今日进度和“今日清空”包含一次性事项；**历史打卡完成率的分子/分母只统计每日重复事项**，避免一次性事项污染长期比例。

### F.5 已知边界

- AI 解析不能保证 100% 准确，因此必须经过预览确认。
- 预览里可改标题、重复方式、提醒时间；一次性事项的自定义日期暂不支持在预览里改（可切换为“仅今天”或“每天”）。
- 语音输入需要麦克风权限；H5 需要 HTTPS 或 localhost，识别走后端 `/api/transcribe`，前端不保存 ASR 密钥。
- 当前每条消息独立解析，不支持跨消息上下文合并（如“第二项改成 9 点”）；可以重新发送完整描述。
- 取消/闲聊的本地短语表覆盖常见说法；更口语化的表达依赖模型判断，模型不可用时可能被本地规则误识别为事项。
- 不支持从 App 外部（微信等）发消息创建事项；那需要账号同步与服务端存储，属于后续阶段。
- 原生提醒仍需 HBuilderX 自定义基座真机验证；H5 只在页面打开时提醒。
