# 后端更新与部署操作手册

> 适用：每次修改了 `src/`、`scripts/`、后端依赖或图谱数据后，把新版本发布到阿里云服务器。
> 目标：**可重复、可验证、可回滚**；不覆盖服务器上的 `.env`，不误删用户数据库。
>
> 本文不记录任何密码、私钥、真实密钥。SSH 密码由你在终端自己输入，不要发给别人。

## 1. 更新前检查（本地）

在项目根目录确认：

```powershell
cd D:\IKGR-system-eands

.venv/Scripts/python.exe -m pytest tests/ -q
```

要求：

- 测试通过（当前基线：`95 passed, 1 skipped`）；
- 知道这次改了哪些文件；
- **不要把 `.env`、`data/app/ikgr.db` 打进部署包**。

## 2. 本地打包（Windows PowerShell）

只打包后端代码和启动脚本；`.env`、数据库、虚拟环境、前端都不打包。

```powershell
cd D:\IKGR-system-eands

# 1) 清理旧 staging 和旧包
Remove-Item D:\ikgr-deploy -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item D:\ikgr-backend.zip -Force -ErrorAction SilentlyContinue

# 2) 建 staging，只复制需要更新的内容
New-Item -ItemType Directory -Path D:\ikgr-deploy | Out-Null
Copy-Item src           -Destination D:\ikgr-deploy -Recurse
Copy-Item scripts       -Destination D:\ikgr-deploy -Recurse
Copy-Item requirements-server.txt -Destination D:\ikgr-deploy

# 3) 只有在图谱 JSON 变化时才复制数据（一般不需要）
# New-Item -ItemType Directory -Path D:\ikgr-deploy\data\raw -Force | Out-Null
# Copy-Item data\raw\math.json -Destination D:\ikgr-deploy\data\raw
# New-Item -ItemType Directory -Path D:\ikgr-deploy\data\processed -Force | Out-Null
# Copy-Item data\processed\math_5b_knowledge_graph.json -Destination D:\ikgr-deploy\data\processed

# 4) 压缩
Compress-Archive -Path D:\ikgr-deploy\* -DestinationPath D:\ikgr-backend.zip -Force

# 5) 确认包里没有 .env 和数据库
Remove-Item D:\ikgr-deploy-check -Recurse -Force -ErrorAction SilentlyContinue
Expand-Archive D:\ikgr-backend.zip -DestinationPath D:\ikgr-deploy-check -Force
Get-ChildItem D:\ikgr-deploy-check -Recurse -Filter ".env"
Get-ChildItem D:\ikgr-deploy-check -Recurse -Filter "*.db"
Remove-Item D:\ikgr-deploy-check -Recurse -Force
```

期望：最后两条 `Get-ChildItem` **没有输出**。如果出现 `.env` 或 `.db`，不要上传。

## 3. 上传到服务器（本地 PowerShell）

```powershell
scp D:\ikgr-backend.zip root@114.55.116.162:/root/
```

- 首次连接会问 `yes/no`，输入 `yes`；
- 然后输入服务器密码（你自己输入，不显示字符）；
- 如果提示 `scp 不是命令`，把 `C:\Windows\System32\OpenSSH\` 加入 PATH，或新开终端。

## 4. 登录服务器并备份

```powershell
ssh root@114.55.116.162
```

登录后（提示符类似 `root@iZ...:~#`）：

```bash
# 4.1 备份当前代码
cd /opt/ikgr
TS=$(date +%Y%m%d%H%M%S)
tar czf /root/ikgr_code_backup_${TS}.tgz src scripts requirements-server.txt
echo "code backup: /root/ikgr_code_backup_${TS}.tgz"

# 4.2 停服务，避免备份/覆盖时还有写入
systemctl stop ikgr

# 4.3 备份数据库（SQLite 在线备份 API，WAL 也安全）
mkdir -p data/app/backups
.venv/bin/python -c "from src import db; c=db.connect(); db.backup(c, 'data/app/backups/ikgr_before_deploy_${TS}.db'); c.close()"
echo "db backup: data/app/backups/ikgr_before_deploy_${TS}.db"

# 4.4 记录当前版本状态（可选）
.venv/bin/python scripts/migrate.py status || true
```

> 备份文件名带时间戳，回滚时用得到。不要删除 `data/app/backups/`。

## 5. 解压并替换代码

```bash
# 5.1 解压到临时目录
rm -rf /root/ikgr-deploy
mkdir -p /root/ikgr-deploy
unzip -o /root/ikgr-backend.zip -d /root/ikgr-deploy

# 5.2 替换 src / scripts（整目录替换，避免旧文件残留）
cd /opt/ikgr
rm -rf src scripts
cp -r /root/ikgr-deploy/src /opt/ikgr/
cp -r /root/ikgr-deploy/scripts /opt/ikgr/
cp /root/ikgr-deploy/requirements-server.txt /opt/ikgr/

# 5.3 不要覆盖 .env 和 data/app
ls -la /opt/ikgr/.env
ls -la /opt/ikgr/data/app/ikgr.db
```

> 如果这次没有新增依赖，第 6 步可以跳过；不确定就执行一次，pip 会很快判断。
> **绝对不要**把本地的 `.env` 覆盖到服务器；服务器上的 Qwen 密钥以服务器 `.env` 为准。

## 6. 安装依赖（依赖有变化时）

```bash
cd /opt/ikgr
.venv/bin/pip install -r requirements-server.txt
```

本项目的认证使用 Python 标准库 `hashlib.scrypt`；语音上传接口 `/api/transcribe`
依赖 `python-multipart`（已在 `requirements-server.txt` 中）。本次若新增了语音功能，
必须执行一次第 6 步安装依赖，并在服务器 `.env` 里补上语音识别配置（见 6.1）。

### 6.1 语音识别（ASR）环境变量

语音转文字使用阿里云百炼 Qwen-ASR（`qwen3-asr-flash`）的 OpenAI 兼容
Chat Completions 接口。**真实值只放在服务器** `/opt/ikgr/.env`，不要写进
代码、前端、APK、H5 或文档，也不要提交到 Git。

在 `/opt/ikgr/.env` 追加（占位值如下，实际值以百炼控制台为准）：

```bash
ASR_API_KEY=sk-你的语音识别密钥
ASR_BASE_URL=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
ASR_MODEL=qwen3-asr-flash
```

- `ASR_BASE_URL` 使用**地域 / Workspace 专属地址**，必须与 Key 的归属一致：
  北京用 `cn-beijing...`，新加坡用 `ap-southeast-1...`；没有专属地址时，
  可用同地域公共地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
- 修改 `.env` 后执行 `systemctl restart ikgr`；环境变量只在进程启动时读取。
- 未配置时 `POST /api/transcribe` 返回 502「语音识别服务未配置」，不影响问答、
  登录和其他功能。
- 语音识别与文本生成是两套独立配置（`ASR_*` 与 `QWEN_*`），可以填同一个百炼
  Key，但不要混用模型名。

**调用边界**：H5 与 Android APK 只访问本后端的 `POST /api/transcribe`，由后端
再请求百炼。前端不持有 ASR Key，也不直接请求 Qwen/百炼接口；不要把
`ASR_API_KEY` 打包进 APK 或写进 H5 代码。

**验证**：

```bash
curl -sS -F "file=@test.mp3" http://127.0.0.1:18080/api/transcribe
```

期望返回 `{"text":"..."}`。401/403 先检查 Key 与地域/Workspace 是否匹配；
502 看 `journalctl -u ikgr -n 100 --no-pager` 里的上游状态码。

## 8. 图谱数据更新（仅当 JSON 变化时）

一般代码更新**不需要**重新导入图谱。只有原始/子图 JSON 变化时才执行：

```bash
cd /opt/ikgr

# 全量数学图谱（内容未变会自动跳过）
.venv/bin/python scripts/import_graph.py \
  --json data/raw/math.json --scope subject_full

.venv/bin/python scripts/import_graph.py \
  --json data/processed/math_5b_knowledge_graph.json \
```

- 内容变化时脚本会报错要求 `--force`；确认要覆盖时再加 `--force`；
- 原始 JSON 不会被删除或覆盖；
- 导入前已有第 4 步的数据库备份。

```bash
systemctl start ikgr

journalctl -u ikgr -n 50 --no-pager
```

验证 1：本机根路径

```bash
curl -sS http://127.0.0.1:18080/
```

期望：

```json
{"service":"中小学教材知识图谱智能问答系统","docs":"/docs"}
```

验证 2：认证路由是否存在（短密码探测，不会创建用户）

```bash
curl -sS -o /dev/null -w "%{http_code}\n" \
  -X POST http://127.0.0.1:18080/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"probe_check","password":"short"}'
```

- 返回 **422**：新代码已生效（参数校验失败，路由存在）；
- 返回 **404**：服务器还是旧代码，检查第 5 步替换是否成功；
- 返回 **500**：看 `journalctl -u ikgr -n 100`，多半是数据库没迁移或依赖缺失。

验证 3：Swagger 文档

```bash
curl -sS http://127.0.0.1:18080/openapi.json | head -c 200
```

验证 4：从你自己的电脑访问公网

```powershell
curl.exe http://114.55.116.162:18080/
```

## 10. 回滚（部署失败时）

### 10.1 只回滚代码

```bash
systemctl stop ikgr
cd /opt/ikgr
rm -rf src scripts
tar xzf /root/ikgr_code_backup_<时间戳>.tgz -C /opt/ikgr
systemctl start ikgr
systemctl status ikgr --no-pager
```

### 10.2 代码 + 数据库一起回滚

```bash
systemctl stop ikgr
cd /opt/ikgr

# 先回滚代码
rm -rf src scripts
tar xzf /root/ikgr_code_backup_<时间戳>.tgz -C /opt/ikgr

# 再恢复数据库（会丢失部署后产生的新数据，确认后再做）
cp data/app/backups/ikgr_before_deploy_<时间戳>.db data/app/ikgr.db
rm -f data/app/ikgr.db-wal data/app/ikgr.db-shm

systemctl start ikgr
curl -sS http://127.0.0.1:18080/
```

> 回滚数据库会丢失部署后的新用户/新会话；只有确认是迁移/导入导致故障时才这样做。

## 11. 手机连局域网失败怎么判断

先判断手机访问的是哪条链路：

| 手机访问方式 | API 地址来源 | 常见问题 |
| --- | --- | --- |
| 手机浏览器打开 `http://192.168.1.31:5173/`（H5 dev） | `app/src/config.js` 的 `BASE_URL` | `BASE_URL` 还写 `127.0.0.1` → 手机访问的是手机自己 |
| 手机安装 APK | 打包时写死的 `BASE_URL` | 旧 APK 可能仍指向公网旧后端 |
| 手机浏览器直接开公网地址 | 公网后端 | 公网后端未更新 → 注册/登录 404 |

### 11.1 正确的局域网配置

1. 电脑和手机连**同一个 Wi-Fi**；
2. 后端用 `--host 0.0.0.0`：
   ```powershell
   .venv/Scripts/python.exe -m uvicorn src.api:app --host 0.0.0.0 --port 18080
   ```
3. 查电脑 WLAN IP：
   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 -InterfaceAlias WLAN | Select-Object IPAddress
   ```
   当前是 `192.168.1.31`；
4. 把 `app/src/config.js` 改成：
   ```js
   export const BASE_URL = 'http://192.168.1.31:18080'
   ```
5. 手机浏览器先测后端：
   ```text
   http://192.168.1.31:18080/
   ```
   能看到 JSON 才说明网络通；
6. 再打开 H5：
   ```text
   http://192.168.1.31:5173/
   ```
7. Windows 防火墙允许 Python/Node 的“专用网络”入站；如果手机还是打不开，检查路由器是否开启了 AP 隔离、手机是否连了 VPN。

### 11.2 为什么 `127.0.0.1` 在手机上不行

`127.0.0.1` 永远表示“当前设备自己”。手机上的 `127.0.0.1:18080` 是手机自己的 18080，不是电脑的。手机必须用电脑的局域网 IP，例如 `192.168.1.31`。

### 11.3 是不是公网后端没更新？

**如果手机/APK 用的是 `http://114.55.116.162:18080`，是的。** 目前公网 `/api/auth/register` 实测返回 **404**，说明服务器上还是旧代码，没有注册/登录/聊天历史接口。

解决方式二选一：

- **本地局域网测试**：按 11.1 把 `BASE_URL` 改成 `http://192.168.1.31:18080`；
- **更新公网后端**：按本文第 2–9 节重新打包、上传、替换、迁移、重启；再验证 `422` 探针。更新公网后仍要注意 HTTP/ICP 风险，别用真实密码。

## 13. 安全边界

- **不要把 `.env` 打进 zip**；服务器 `.env` 单独维护，权限建议 `chmod 600`。
- **ASR 密钥只在服务器**：H5 与 APK 只调用后端 `/api/transcribe`，不直接请求 Qwen/百炼；
  不要把 `ASR_API_KEY` 写进前端代码或打包进 APK。
- **不要把 `data/app/ikgr.db` 提交到 Git 或打进代码包**；它是用户数据。
- 备份文件包含用户数据，限制访问权限，不要发到公开网盘。
- 本文所有密码/密钥都用占位符；不要把自己的真实密码写进文档或聊天。
- 公网 HTTPS/ICP 完成前，不要在公网 HTTP 上使用真实学生账号密码。
- 部署完成后如需收紧访问，可把 uvicorn 改为只监听 `127.0.0.1`，由 Nginx 反向代理对外提供 HTTPS（阶段 2.5）。
