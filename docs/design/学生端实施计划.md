## 3. 已完成阶段摘要

### 阶段 0：代码与数据现状盘点

结论：

- 后端入口 `POST /api/ask`，无认证、无持久化；前端 `app/` 已有问答页和学习路径页。
- 图谱以 JSON 保存：全量数学 2711 节点 / 5273 边；五年级下册子图 67 节点 / 92 边。
- 635 条特殊边（`tests_concept` 406 + `tests_skill` 229）没有标量 target，需要用
  `graph_edge_targets` 统一展开。
- 公网当时是 HTTP、CORS 为 `*`；真实账号测试必须等 HTTPS。
- 测试基线当时为 `47 passed, 1 skipped`。

### 阶段 1：学生端需求与数据/API 设计

产出：[学生端数据与接口设计.md](学生端数据与接口设计.md)。

关键决定：

- 用户名 + 密码，不收集手机号/邮箱；注册固定 `student`；老师/管理员仅后台脚本创建。
- 密码只存 scrypt 哈希；登录用不透明随机令牌，服务端只存 SHA-256。
- 游客可问答但不落库；登录后保存会话/消息。
- 会话软删除；聊天记录按会话展示；MVP 不把前几轮传给模型。
- SQLite 版本化迁移；表结构按 PostgreSQL 可迁移方式设计。

### 阶段 2：SQLite 基础结构与课程图谱导入

结果：

- 建库/迁移脚本：`scripts/migrate.py`；图谱导入：`scripts/import_graph.py`。
- 建好 11 张基础表（后续扩展到 14 张）；外键、索引、WAL、版本化迁移可用。
- 导入全量数学图谱（2711 节点 / 5273 边 / 5336 目标行）和 5b 子图（67 节点 / 92 边）。
- 635 条特殊边全部进入 `graph_edge_targets`，目标行 698 条，无漏数据。
- 原始 JSON 不删除、不覆盖；导入前备份，重复执行有策略。
- 本阶段未接入登录、未改问答运行链路。

### 阶段 2.5：HTTPS 反向代理与部署加固

原计划因 ICP 备案暂停；后续已完成：

- `https://seventeen17.com.cn` 已启用 Nginx + Let's Encrypt，HTTP 301 跳转 HTTPS。
- 前端 `app/src/config.js` 使用 `https://seventeen17.com.cn`。
- 后端由 Nginx 反代到 `127.0.0.1:18080`；生产环境应收紧安全组 18080。
- 详细步骤见 [HTTPS 部署指南](../deploy/HTTPS部署指南.md)。

### 阶段 3：后端学生注册、登录与身份校验

结果：

- 新增 7 个后端模块：`settings.py`、`security.py`、`rate_limit.py`、`errors.py`、
  `auth_service.py`、`auth_deps.py`、`auth_api.py`。
- 修改 `src/api.py` 注册认证路由；`.env.example` 增加认证配置占位项。
- 4 个接口：注册（自动登录）、登录、当前用户、退出。
- 密码 scrypt；令牌随机 + SHA-256 存储；30 天过期、撤销、多设备。
- 注册只能创建 `student`；老师/管理员仅后台脚本。
- 新增 `tests/test_auth.py`（19 项）；本阶段未实现前端页面和聊天历史 API。

### 阶段 4：前端登录、注册和登录状态

结果：

- 新增认证页、顶部登录状态、令牌存取/清除、401 处理、退出。
- 令牌键：`ikgr.auth.token`、`ikgr.auth.user`；退出/401 清除。
- 游客问答保持不变；登录后使用真实后端身份，不伪造本地用户。
- H5 构建通过；前端与真实后端联调通过。

### 阶段 5：聊天会话和消息持久化

结果：

- 登录后问答落库；游客不落库；`/api/ask` 保持兼容。
- 会话列表、消息分页、软删除、失败记录、`client_request_id` 幂等重试。
- 越权访问统一 404；消息保存图谱版本、知识点、出处、拒答状态。
- 前端新增历史页，可打开历史会话、删除会话。
- H5 构建通过；前端 API 与真实后端历史联调通过。
- 本阶段未实现老师统计和 DuckDB 管道。

## 4. 阶段 6 待办（未完成）

目标：从注册到跨会话读取历史完整走查，补齐使用说明和已知限制；公网验证必须走 HTTPS。

### 4.1 端到端检查

- [ ] 注册 → 自动登录 → 退出 → 重新登录。
- [ ] 创建会话 → 发送问题 → 查看历史 → 继续追问。
- [ ] 两个学生账号之间的数据隔离；访问别人的会话返回 404。
- [ ] 无效/过期令牌返回 401，前端清除本地状态并跳登录。
- [ ] 游客问答不落库；游客带 `conversation_id` 返回 401。
- [ ] 失败回答可重试；`client_request_id` 去重生效。
- [ ] 附件、语音、视频、资料编辑等新增功能回归。

### 4.2 HTTPS 与部署检查

- [ ] 证书链、有效期、续期任务正常。
- [ ] HTTP → HTTPS 301 跳转。
- [ ] Nginx 代理头、CORS、后端 18080 仅本机可访问。
- [ ] 旧 APK 是否仍指向 HTTP；需要时重新云打包。
- [ ] 手机 4G 访问域名、语音输入正常。

### 4.3 文档收尾

- [ ] 更新根 README 的目录结构、部署链接、API 列表、进度清单。
- [ ] 补充学生端使用说明、部署环境配置、备份/恢复方法。
- [ ] 记录已知限制和老师端后续工作建议。
- [ ] 汇总实际执行的命令、每项结果、手动验证步骤。

### 4.4 验证原则

- 优先使用项目已有测试和可重复的手动步骤；新增测试先说明覆盖目标。
- 不得使用或输出真实用户密码、生产密钥或真实个人数据。
- 公网验证必须使用 HTTPS；不得用自签证书或“本地 curl 通过”代替。

## 5. 关键约束

1. 每次只执行一个阶段，完成并经审阅后再进入下一阶段。
2. 不在文档、示例或代码中写真实密码、密钥或其他机密。
3. 不删除现有数据或覆盖原始图谱；数据迁移必须提供备份、重复执行策略和回滚说明。
4. 改动范围保持在本阶段内；发现额外问题先记录。
5. 每个阶段必须报告：改了什么、为什么、用户能做什么、涉及文件/接口/表、验证结果、遗留问题。
6. 没有运行验证时要说明原因，不得声称验证通过。
