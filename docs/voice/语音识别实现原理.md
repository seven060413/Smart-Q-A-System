## 一、配置分布在四个地方

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 密钥 / 地址 | `.env` 的 `ASR_API_KEY`、`ASR_BASE_URL`、`ASR_MODEL` | 由 [src/speech.py:56-58](../../src/speech.py#L56-L58) 在进程启动时读取 |
| 后端接口 | [src/api.py:305](../../src/api.py#L305) | 定义 `POST /api/transcribe`；大小上限在 [273](../../src/api.py#L273)，格式表在 [276](../../src/api.py#L276) |
| 前端上传 | [app/src/api.js:94](../../app/src/api.js#L94) | `transcribeAudio()` 用 `uni.uploadFile` 发 multipart；App 传 `filePath`，H5 传 `file`（File 对象） |
| 前端录音 | [app/src/pages/index/index.vue:173-194](../../app/src/pages/index/index.vue#L173-L194) | App 用 RecorderManager（开始 [662](../../app/src/pages/index/index.vue#L662)）；H5 用 MediaRecorder（开始 [510](../../app/src/pages/index/index.vue#L510)，结束 [588](../../app/src/pages/index/index.vue#L588)）；上传 [726](../../app/src/pages/index/index.vue#L726) |

另外：

- 前端访问的后端地址在 [app/src/config.js](../../app/src/config.js) 的 `BASE_URL`。
- APK 的麦克风权限在 [app/src/manifest.json](../../app/src/manifest.json) 的 `RECORD_AUDIO`，只对打包后的 APK 生效。
- App 用 `uni.getRecorderManager()`；H5 官方不支持该 API，改用浏览器 `MediaRecorder`，并要求 HTTPS 或 localhost。

> 环境变量只在**进程启动时**读取一次，修改 `.env` 后必须重启后端。

## 二、完整识别过程

```text
① 点麦克风
   App：Android 用 plus.android.requestPermissions 申请 RECORD_AUDIO；
        iOS 首次录音由系统弹窗；
        uni.getRecorderManager().start()，mp3 / 16kHz / 30 秒
   H5：检查安全上下文、MediaRecorder 与 getUserMedia；
        优先选 MP4/AAC，浏览器只提供 webm/ogg 时录完转 WAV

② 再点一次（或录满 30 秒）
   App：recorder.onStop() 拿到 tempFilePath
   H5：MediaRecorder.stop()，把 chunk 合成 Blob
   检查时长：小于 0.5 秒 → 提示“没有录到有效语音”

③ 上传
   App：transcribeAudio(filePath)
   H5：Blob → File，transcribeAudio(null, { file })
   统一 POST {BASE_URL}/api/transcribe，multipart 字段名 file
   音频以二进制上传，不转 Base64 放进 JSON

④ 后端校验（src/api.py）
   读入内存，最多 5MB + 1 字节
   空文件 → 400 EMPTY_FILE
   超过 5MB → 413 AUDIO_TOO_LARGE
   读前 16 字节判断文件头（mp3 / wav / ogg / webm / m4a / flac）
   不认识 → 400 UNSUPPORTED_FORMAT

⑤ 调用识别（src/speech.py）
   检查 ASR_API_KEY、ASR_BASE_URL 是否配置
   把音频字节 base64 编码，拼成：
     data:audio/mpeg;base64,<...>
   用 OpenAI SDK 请求 ASR_BASE_URL：
     model = qwen3-asr-flash
     messages = [{ role: user,
                   content: [{ type: input_audio,
                               input_audio: { data: <Data URL> } }] }]
     stream = false
   超时 30 秒；失败按类型映射为 400 / 502 / 504

⑥ 百炼返回
   choices[0].message.content = "你好，大家好，我是谢文婷。"
   speech.py 取出并 strip，得到干净文本

⑦ 返回前端
   {"text":"你好，大家好，我是谢文婷。"}
   index.vue 把文字填进输入框：
     已有内容 → 追加并加空格
     没有内容 → 直接填入
   ★ 不会自动发送

⑧ 用户校对后点“发送”
   走的还是原来的 /api/ask，检索、图谱、生成逻辑完全没变
```

## 三、设计原理

### 1. 为什么密钥只在后端

前端只上传音频，不持有任何 Key。Key 从 `.env` 读进 `SpeechTranscriber`，
请求由后端发往百炼。这样即使 APK 被反编译，也拿不到密钥。

### 2. 为什么用 Data URL

Qwen-ASR 的 OpenAI 兼容接口不接受本地文件路径，只接受“公网 URL”或
`data:<mediatype>;base64,<data>`。后端把内存里的音频字节编码后放进
`input_audio`，并带上真实 MIME（mp3 → `audio/mpeg`）。
5MB 原始音频编码后约 6.7MB，仍在百炼 10MB 上限内。

### 3. 为什么音频不落盘

`file.file.read()` 把音频读进内存，识别完即丢弃；不写临时文件、不保存录音。
日志只记录模型名、状态码、耗时和字数，**不记录 Key、音频内容或转写文本**。

### 4. 为什么识别完不自动发问

语音识别可能出错（同音字、数字、断句），所以文字先回填输入框，让用户检查、
修改后再走原有的“发送”按钮。语音只负责“把话变成字”，不参与问答流水线。

### 5. 为什么 H5 要单独实现

uni-app 官方平台支持表里 `uni.getRecorderManager` 的 H5 一项是“不支持”，
所以 App 和 H5 用两套录音实现：

- **App**：RecorderManager → mp3（16kHz、30 秒上限）；
- **H5**：MediaRecorder → 优先 `audio/mp4`（AAC）；浏览器只提供 webm/ogg 时，
  用 Web Audio 解码并转成 **16kHz 单声道 WAV** 再上传（WAV 是 Qwen 明确支持的格式）。

H5 麦克风要求安全上下文（HTTPS 或 localhost），用局域网 IP 的 http 地址会被浏览器拒绝。
上传仍走同一个 `/api/transcribe`：H5 通过 `uni.uploadFile` 的 `file` 参数传 File 对象，
App 通过 `filePath` 传本机临时文件。curl 能直接测通后端，是因为它绕过了浏览器和前端。

## 五、验证与排错

最简单的验证方式是直接调用接口：

```powershell
curl.exe -F "file=@D:\test.mp3" http://127.0.0.1:18080/api/transcribe
```

成功返回：

```json
{"text":"你好，大家好，我是谢文婷。"}
```

常见错误：

| 返回 | 含义 | 处理 |
| --- | --- | --- |
| 502 `ASR_NOT_CONFIGURED` | `.env` 缺 Key 或 Base URL | 补齐后重启 |
| 401 / 403 | Key 与地址的地域/业务空间不匹配 | 见 [配置步骤](语音识别配置步骤.md) |
| 400 `NO_SPEECH` | 静音、太短、没说话 | 重录 |
| 400 `UNSUPPORTED_FORMAT` | 文件头不是支持的格式 | 用 mp3/wav |
| 413 `AUDIO_TOO_LARGE` | 超过 5MB | 缩短录音 |
| 502 `ASR_UPSTREAM_ERROR` | 百炼拒绝音频或服务异常 | 看日志里的上游状态码 |
| 504 `ASR_TIMEOUT` | 请求超时 | 重试或检查网络 |
