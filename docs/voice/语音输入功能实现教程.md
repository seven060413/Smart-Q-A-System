# 语音输入功能实现教程

> 适用于本项目的 uni-app（Vue 3）前端、FastAPI 后端和 Android APK/H5 构建。本文说明推荐架构、实施步骤与验收方法；当前仓库尚未接入录音或语音识别服务。

## 1. 推荐方案

在聊天输入栏增加麦克风按钮。用户点击后开始录音，再次点击结束录音；前端将录音文件上传到后端的语音识别接口。后端调用选定的中文 ASR（自动语音识别）服务，返回转写文字。前端把文字放入现有输入框，允许用户修改后点击“发送”。最终问题仍通过当前 `POST /api/ask` 提交。

```text
麦克风按钮 → uni recorder → 音频文件
                            ↓ 上传
                        FastAPI /api/transcribe → ASR 服务
                            ↓ { text: "..." }
输入框（用户校对） → 现有 /api/ask → 问答结果
```

此流程不改变知识图谱、检索和问答逻辑；语音只负责把口述问题变成文本。采用前端录音、服务端识别，可以共用一套识别逻辑，不依赖各浏览器不一致的 Web Speech API，也避免把云服务密钥放进 APK 或网页代码。

## 2. 本项目的接入位置

当前聊天页是 `app/src/pages/index/index.vue`，输入框绑定 `question`，`send()` 调用 `askQuestion(q)`。API 封装位于 `app/src/api.js`。FastAPI 应用位于 `src/api.py`，现有 `/api/ask` 只接收 `question` 字段。

建议新增：

- 前端录音状态与开始/结束/取消操作；
- `app/src/api.js` 中的 `transcribeAudio(filePath)` 上传封装；
- 后端 `POST /api/transcribe` 音频上传接口；
- 服务端 ASR 适配层及环境变量配置；
- Android 麦克风权限与隐私说明。

无需改动 `/api/ask`、`src/pipeline.py` 或问答响应格式。

## 3. 为什么选服务端 ASR

### 推荐：客户端录音 + 服务端调用云 ASR

- Android APK 与 H5 都把音频发到同一个接口；
- 识别供应商密钥只保存在后端环境变量；
- 可以限制上传时长、文件大小和格式，并统一错误提示；
- 后续更换供应商时，前端交互和问答接口保持不变。

代价是需要选择一个 ASR 供应商、配置其密钥，并承担网络请求延迟和可能的调用费用。选择时核对普通话/中文支持、短音频接口、支持的音频格式、免费额度与价格、数据保存和隐私条款，以及服务区域网络可达性。项目目前使用阿里云 Qwen 生成答案，不代表已经有语音识别服务或 ASR 额度；不要把文本生成 API 当作语音识别 API。

### 备选：浏览器 Web Speech API

只适合做 H5 快速原型。浏览器、设备和权限策略差异较大，部分实现依赖浏览器厂商在线服务；Android App-Plus 中也不能假定 `window.SpeechRecognition` 存在。因此若要覆盖 APK 和 H5，不建议把它作为唯一方案。

### 备选：纯原生/设备语音识别

可能依赖设备系统版本、厂商服务或额外原生插件；在 uni-app Android 基座和 H5 的行为不一致。除非项目明确限定设备和插件供应，否则统一服务端 ASR 更适合作为首个可交付版本。

## 4. 交互设计

建议采用“点按开始、点按结束”，而不是长按：H5 鼠标/触屏、Android 手势、页面滚动以及误触的处理更一致。

1. 输入栏放置麦克风按钮；录音时显示“正在录音 · 点击结束”和计时/明显状态色。
2. 录音结束后自动上传；上传时按钮禁用并显示“正在识别…”。
3. 识别成功后将文字填入 `question`，焦点/光标留在输入框，**不要自动发送**。
4. 用户可以校对、补充或清空，再点现有“发送”按钮。
5. 允许取消录音；取消不应上传文件或清除用户已有输入。
6. 权限拒绝、无语音、网络失败、服务超时和不支持的平台均给出清晰提示，并保留用户已有文本。
7. 同一时间只允许一个录音/转写任务；问答加载中禁用录音，录音或转写中禁用发送。

## 5. uni-app 前端实施步骤

### 5.1 录音 API

使用 uni-app 的 `uni.getRecorderManager()` 获取录音管理器，并监听 `onStart`、`onStop`、`onError`。通过 `start()` 配置录音时长、采样率、声道数和编码格式，通过 `stop()` 结束。按 uni-app/DCloud 当前版本的官方文档核对 Android App-Plus 与 H5 支持情况，以及 `tempFilePath` 和录音参数；不要直接照搬某个旧版本的示例。

建议首版将最长录音限制在 30 秒以内，单声道、16 kHz、MP3 或服务商明确支持的格式。具体编码参数要以目标平台和 ASR 服务兼容性为准；若 H5 无法生成所选格式，应按平台选可用格式或在服务端统一转码，不能只改文件扩展名伪装格式。

录音管理器建议在页面初始化时创建，卸载时清理监听/停止正在录制的会话。处理用户在录音中离开页面、App 进入后台、重复点击开始/结束、系统来电打断等状态，避免录音状态卡住。页面代码需使用小状态机（如 `idle → recording → uploading → idle`），并在所有成功、失败、取消分支复位。

### 5.2 上传封装

在 `app/src/api.js` 新增独立的 `transcribeAudio(filePath)`，通过 `uni.uploadFile` 上传到：

```text
POST ${BASE_URL}/api/transcribe
字段名：file
响应：{"text":"识别出的文字"}
```

uni.uploadFile 通常把 JSON 响应放在 `res.data` 字符串中，需要安全 `JSON.parse` 并处理非 2xx、空文本、解析错误和超时。上传成功后只更新 `question.value`，不调用 `send()`。

注意：`BASE_URL` 当前为 HTTP 公网演示地址。真机录音上传需要确认 Android 网络安全策略允许访问该地址；正式部署应使用 HTTPS，尤其是 H5 麦克风访问通常要求安全上下文（HTTPS 或 localhost）。H5 页面若经 HTTPS 打开，浏览器可能阻止向 HTTP 后端上传（混合内容），因此前端与后端都应部署 HTTPS。

### 5.3 页面状态

建议新增状态：

```text
recordState: idle | recording | uploading
recordSeconds: 当前录音秒数
```

处理录音结束事件时检查文件路径和时长：太短时提示“没有录到有效语音”；超过限制则停止并上传或提示重录。上传开始后显示进度/忙碌态；如果现有组件不方便显示上传百分比，显示“正在识别…”即可。

### 5.4 Android 权限

在 HBuilderX 的 `manifest.json` / App 权限配置中声明录音所需麦克风权限（Android `RECORD_AUDIO`），并确认运行时权限弹窗会由当前 uni-app 版本或所用插件正确触发。只在用户主动点麦克风时申请，不要启动 App 就申请。拒绝后解释如何在系统设置开启；永久拒绝时不要循环弹窗。

项目当前 `manifest.json` 的 Android 权限列表没有 `RECORD_AUDIO`，需要补充后重新运行到真机/重新云打包。核对云打包后 APK 的实际权限清单。H5 不使用 Android manifest 权限，而由浏览器在录音时请求麦克风授权，并要求安全上下文。

如果目标 uni-app/DCloud 版本未自动处理运行时权限，按官方 App 权限 API 或所用录音插件的文档实现授权检查。避免为了语音功能引入未维护的插件；确认插件兼容 Vue3、当前 uni-app 编译器、Android 基座和 H5 目标。

## 6. FastAPI 后端实施步骤

### 6.1 新增接口

在 `src/api.py` 增加 `POST /api/transcribe`，接收 multipart/form-data 的 `UploadFile`，字段名为 `file`，成功响应为：

```json
{"text":"为什么异分母分数相加要先通分"}
```

接口应做以下校验：

- 只接受 ASR 服务支持的音频 MIME/格式；
- 限制文件大小（首版例如 5 MB）和音频时长（例如 30 秒）；
- 拒绝空文件、格式不符和超限文件；
- 不信任客户端文件名，使用临时文件或内存流，结束后及时删除；
- 设置供应商请求超时，不能无限等待；
- 返回简洁、稳定的错误 JSON，不把密钥或供应商内部报错返回客户端。

`UploadFile` 需要 `python-multipart`。先检查 `requirements-server.txt` 是否已有该依赖；若没有，新增固定兼容版本并更新部署安装步骤。不要将上传内容长期落盘。

### 6.2 ASR 适配层

把供应商调用放在独立模块，例如 `src/speech.py`，而不是堆在 API 路由中。定义清晰的接口，例如 `transcribe(file_bytes, content_type) -> str`。API 层负责上传校验与 HTTP 状态；适配层负责供应商鉴权、音频提交、超时、错误映射和解析识别文本。

供应商密钥放 `.env` / 部署环境，不入库、不传给前端。可用类似 `ASR_API_KEY`、`ASR_BASE_URL`、`ASR_MODEL` 的环境变量，准确变量名以选定供应商方案为准。更新 `.env.example` 时仅放占位符，并更新服务器部署文档。语音识别服务的录音数据处理条款应在上线前确认。

### 6.3 错误码

建议统一返回 JSON 错误，例如 `{"detail":"未识别到有效语音，请重试"}`，并合理区分：

| 状态码 | 场景 |
| --- | --- |
| 400 | 空文件、格式不支持或未检测到语音 |
| 413 | 音频超过大小/时长限制 |
| 502 | ASR 服务不可用或返回异常 |
| 504 | ASR 请求超时 |

返回文本需面向用户；详细异常写服务端日志时不得包含 API 密钥或未经必要的完整录音内容。

## 7. 隐私与安全

- 录音应由用户明确点击触发，界面持续显示正在录音；结束后立即停止麦克风。
- 上传前告知录音会用于语音转文字并发送至识别服务；如有正式用户/未成年人使用，确认适用的隐私告知和监护人要求。
- 只上传识别必需的短音频；不在应用或服务器保留原始录音，除非业务确有需要且已明确告知。
- 服务密钥只保存在服务器；生产环境配置 HTTPS、上传限额和请求频率限制。
- 关闭录音时清理临时文件和监听器；避免把音频路径、音频内容、密钥写入普通日志。

## 8. 实施顺序

1. 选定 ASR 服务，核对中文、音频格式、HTTP 接口、价格、数据处理条款和部署网络可达性。
2. 后端先实现适配层与 `/api/transcribe`，用一段短录音验证接口和错误处理。
3. 前端增加录音按钮、录音状态、取消/超时、文件上传和转写结果回填。
4. 配置 Android 麦克风权限；在 H5 HTTPS 环境检查浏览器权限和上传跨域/混合内容。
5. 在真机及 H5 逐项验收；确认无麦克风权限、无网络、无语音和服务端错误均能恢复。
6. 更新 `.env.example`、依赖、部署指南、隐私说明，再重新构建 H5 和 APK。

## 9. 验收清单

- [ ] 首次点麦克风时按需请求权限，拒绝后文字输入和问答仍可用。
- [ ] 开始/停止状态显示明确，重复操作和录音中离开页面不会卡死。
- [ ] 普通话短句能转写成输入框文字，不会自动提交问题。
- [ ] 用户已有输入时，识别结果采用明确策略（建议追加并加空格，或提示替换），不会静默覆盖。
- [ ] 可以手动修改识别结果并正常调用现有 `/api/ask`。
- [ ] 静音、太短、超时、网络断开、ASR 错误、文件超限均有可理解提示，且可重试。
- [ ] Android APK 在目标真机上获得麦克风权限并可录音；H5 在 HTTPS 页面可授权并工作。
- [ ] 上传不暴露 ASR 密钥；临时录音在识别结束/取消后清理。
- [ ] 后端接口只收支持格式和限额内的音频；日志不泄露密钥和录音内容。

## 10. 项目相关注意事项

- `app/src/pages/index/index.vue` 现有 `send()` 有 `loading` 防重入；需要新增录音/上传状态，并在发问期间禁止开始录音。
- 页面目前只用 `uni.request` 访问 JSON API，上传音频应新增 `uni.uploadFile` 封装，不要把音频转 Base64 放入 JSON，避免体积膨胀。
- `src/api.py` 在模块导入时初始化图谱和 Qwen 生成器；语音接口不应为了转写额外初始化另一套大模型，采用供应商短音频 API 即可。
- 现有演示后端地址是 HTTP。H5 HTTPS 与 HTTP API 混用可能被浏览器拦截；生产方案应给前后端配置 HTTPS。
- 当前 `app/src/manifest.json` 有 Android 权限列表但未列录音权限；加权限后必须重新制作 APK，旧 APK 不会自动获得新权限。
